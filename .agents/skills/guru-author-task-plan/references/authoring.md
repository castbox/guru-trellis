# Current planning authoring contract

## Entry and dependencies

Before each write batch resolve the same live TaskId, generation, source role,
C3/C4 checkout and C5 session through their existing owners. Ordinary dirty
task work is valid; identity mismatch returns to resolution or its named stop.
Do not create replacement tasks or reset branches. Freshly read Direct Source,
selected comments, explicitly introduced requirement/design authority, current
docs and repository evidence. Adjacent `source_selection` retains the #250
locator/section/authority_kind shape. Lost selection is refreshed by original
Clarify/context; PRD or metadata cannot reconstruct that semantic selection.

## Eight profiles

| Profile | Required original input and forward behavior |
| --- | --- |
| initial_review | Current created/Phase 1 route and source_selection: converge requirements and real candidate, return requirements_ready. |
| active_task_scope_change | Actual Clarify scope_ready via the original clear-router: mode/task_ref/source_selection/revision_refs with fixed profile=active_task_scope_change; no already-updated planning is required: preserve identity and revise affected requirements/candidate. |
| wording_reentry | Actual content_changed change_refs: reread docs; equivalent wording can return plan_ready; changed design facts return requirements_ready. |
| approval_revision | Actual revision_actions: revise their concrete gaps; requirements/design change returns requirements_ready, execution-plan-only gap may return plan_ready. |
| delivery_plan_revision | Original router reason delivery_policy_gap or next_independent_delivery plus revision_refs: retain whole scope; revise the unique policy/slice and re-enter earliest affected dependency. |
| requirements_revision | Original requirements router after Clarify, current source_selection and revision_refs: converge current requirements without carrying a caller-preselected decision. |
| solution_planning | Actual candidate_assessment current result, thin architecture_assessment: write design/implement and official JSONL, return plan_ready. |
| architecture_conflict_resolution | Original Architecture planning_purpose and conflict_refs: revise real mechanism candidate; unresolved requirement choice returns clarify_scope. |

All profiles may return clarify_scope for a real scope choice or blocked for a
named authority/input gap. Do not ask routine planning consent for mapped
reentry, technical refinement, missing ephemeral results or absent docs.

## Requirements before substantive solution writing

First write/converge PRD without silently lowering requirements to match current
Architecture. Identify current load-bearing interfaces, mechanisms, ordering,
owners and compatibility commitments. Normative design is a constraint;
advisory design remains advisory. Form the actual minimal call-local candidate:
design_facts + source constraint_refs when design does not exist, otherwise the
current task design_locator. Do not persist another candidate/proposal/cache.
Facts contain mechanisms and responsibility, never PRD narrative, acceptance
claims or approval. Candidate consumption releases it after the current chain.

Invoke original normal-scenario and solution-mechanism owners using their
closed author_candidate_set profile with actual source/candidate locators.
Then invoke root-cause on eligible current candidates. Ordinary feature work
retains not_incident_applicable; mechanism/scope/diagnosis/blocked results follow
their original owners. No proxy Approval profile or qualification cache.
Return requirements_ready. Architecture assesses that object before first
substantive design/implement write. A changed candidate needs fresh assessment.

## Solution writing

Consume only the actual candidate_assessment result from the same current
Architecture call. Apply current baseline, constitution, required project
concerns and checks; use its selected impact/change path and decision refs to
write a genuine task-local contribution and necessary ADR candidate. Shared
promotion stays with original owners after first committed full-diff independent
Branch Review, then fresh Phase 2/commit/full review. No planning promotion.

Design owns the sole source-design disposition matrix: concrete source locator,
original commitment, retain/change/reject, current landing point, rationale,
impact and applicable upstream handling. Check every normative commitment;
retain needs a real landing point. Change/reject cannot silently drop source
authority: product/scope returns Clarify, Architecture returns its owner, other
technical constraints require their actual upstream disposition. If source has
no normative design, state the evidence; never manufacture an empty matrix.
PRD and implement reference this matrix without duplicating it.

Implement owns one Delivery Policy: full by default; partial requires an
independent slice, remaining work and whole-task Completion conditions; staged
requires ordered stages/current stage, entry/exit, remaining stages and final
conditions. Delivery Review checks that policy; Completion judges whole scope;
neither writes policy. Plan one Docs SSOT strategy: ssot_first, delta_first,
bootstrap_or_repair_docs, no_docs_update_needed (decision, never a typed exit).
Name exact contribution/reconciliation consumer and original RDT writer;
delta reconciliation occurs before final Phase 2, not first at Branch Review.
Preserve causal evidence/completion semantics: do not label an inapplicable
feature or package check as incident repair proof.

Author selects business context for official `task.py add-context` in
implement.jsonl/check.jsonl. Official scripts execute writes; they do not decide
context relevance or planning sufficiency. Read actual referenced specs beyond
truncated context injection. No upstream brainstorm writer or hook patch.

## Current gate and recovery

Review the current profile's complete work: source commitments/disposition,
requirements completeness, mechanism/Architecture dependency, policy/Docs plan,
official context, scope boundaries and truthful validation. Then author the
call-local owner result and invoke the objective validator. This result is not
Approval. plan_ready goes to Wording, then fresh final_plan Architecture based
on Wording-current facts, then adjacent Approval. Never replay candidate
assessment into Approval or return a final current result to Author.

No PRD, PRD-only, design-only, three-doc, official seed, partial/stale states
are read and converged here; file count does not determine semantic readiness.
For interruption/compression preserve task identity and refresh the missing
producer. Source/scope change re-enters Clarify then this owner; changed design
re-enters candidate assessment; equivalent wording refreshes only dependent
gates. An informational RelatedWork update alone does not replan. Initial or
active approved plans use original presentation/acceptance/pair guard and
activate/resume_execution; Author never changes lifecycle status. Ordinary
implementation repair and evidence completion stay with their Phase 2 or
Completion owner unless planning authority actually changed.
