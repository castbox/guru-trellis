# 〈Delivery 标题〉需求

写作前实际加载 [共享正文合同](../references/planning-body.md)。以下七节按序填写；全量 D1 也要展开本批正文。共享定义可引用，适用行为与上下文不能只写链接或编号。

## 1. 整体来源与术语

定位公共 accepted_scope、整体 Task PRD、当前 scope_ref/planning_root 及本批必要来源。来源表写 locator、章节、角色和用途；解释本批术语。实际加载关联条件，不重新选择整体范围。

## 2. 整体与本批目标、非目标

说明问题背景、整体目标、本批独立交付目标、覆盖的整体要求及本批排除项。保留整体非目标；不能用复制全量需求掩盖部分交付。

## 3. 本批起点、前序结果、依赖与剩余责任

写实际前序交付事实、当前状态、本批输入/起点、依赖和边界；首次写明尚无前序。说明未交付责任、后续需要的输出及整体 Completion 条件。前序事实附可解析位置，不能伪写 delivered。

## 4. 本批调用方、场景与流程

按场景 ID 填调用方、前置条件、触发动作、处理行为和可观察结果，展开本批分支与顺序。用户故事仅在真实业务角色和值成立时使用；工程场景写真实 caller。

## 5. 完整行为、条件与约束

逐项写当前切片的行为、完整条件、否定、例外、失败结果和约束，关联整体要求和本批场景。保留约定设计承诺，仅引用本批 design 第3节唯一处置；无来源设计时无需制造矩阵。

## 6. 本批验收、验证方式与未决项

每项 AC 写要求/场景、入口、输入和预期观察。说明哪些结果支持后续或整体验收。必要未决项写原 owner、影响及停点；没有则如实说明。当前 requirements 阶段返回 `requirements_ready` 前补齐本批需求，不要求未来方案提前完成。

## 7. Canonical 引用与本轮差额

定位命中的 repo requirement/behavior、design、test 和 Architecture authority 的具体章节及用途；逐项说明本轮实际差额或有依据的无影响。缺 authority 沿原 owner 处理，不造空贡献，不直接改共享导航。后续实施/审核须实际加载必要引用。
