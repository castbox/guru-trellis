## 实际最终标题与正文

下面是实际草稿正文，不是空模板：

## 背景与问题

维护者通过 `check-skill-packages.sh` 的只读检查了解 Guru Team 安装或源码是否一致。当前 `--mode` 接受 `source` 和 `installed`，`--json` 是可选参数。实际运行 `--mode installed --json` 得到一个包含 `status`、`mode`、`facts`、`errors` 的 JSON 对象，检查通过。

当前入口始终输出 JSON。机器读取已有充分字段，但人工查看时需要从完整对象中提取检查结果和问题。本 Issue 改善这一呈现，不声称现有校验逻辑失效。

## 目标与范围

为人工阅读提供明确选择的摘要呈现，使维护者能直接看出检查模式、通过或失败，以及失败时的具体错误。保留现有调用方式、JSON 字段、判断规则和退出码。新增呈现方式的具体参数由后续设计决定。

不修改安装、修复、更新或发布流程，不让摘要决定语义审核结果，不新增自动修复动作。

## 行为要求

1. 对同一次 `source` 或 `installed` 检查，人工摘要使用原 validator 的同一结果。摘要不能另行生成通过或失败结论。
2. 摘要明确显示检查模式、结果和错误。存在错误时逐项呈现原有错误含义；没有错误时明确说明。
3. 未选择摘要时保持现有 JSON 输出。使用 `--json` 的调用仍得到单一 JSON 对象，不夹入说明文字。
4. 检查保持只读。不同呈现方式不改变检查范围、检查结果或退出码。
5. 帮助与使用说明展示人读入口和 JSON 入口，说明二者用途。

## 验收与验证

- 对正常 `source`、`installed` 输入，通过真实入口检查摘要中的模式、结果、错误与原结果一致。
- 对自然存在的普通安装不一致，摘要显示原错误且返回同一非零退出码；不为此引入攻击、压力或故障注入场景。
- 原 `--json` 和未选摘要的调用继续输出可解析的单一 JSON 对象，保留原字段与退出码。
- 检查前后对照工作区，证明呈现选择没有产生仓库写入。
- 帮助中的两个示例命令可以按声明方式执行。
