## Early complete content analysis

`delivery_draft_content_review` independently reads the complete fixed B..H diff,
current scope, plans, contracts, consumers, tests and applicable Architecture.
Its input contains task/key/B/branch_review_commit and no Check field. Review
applicable correctness and both subtraction dimensions. Qualify real findings
under supported normal paths. Do not read Check private conclusions or infer
pass from Draft, CI or phase. Target advancement, PR conflict and absent merge
refs do not change this content range.

After independent semantic analysis, invoke scripts/invoke.sh --input with this
profile and --owner-result containing status, summary, evidence and concrete
revision_refs only for revision-required. Return exactly draft_content_reviewed
(task/key/B/H), draft_revision_required (task/key/revision_refs), or blocked.
The result is call-local feedback; it writes no public full_review, gate or
review cache. Changed HEAD requires current analysis under the shared candidate
contract. The implementation/Check coordinator consumes feedback and separately
judges command facts. Formal delivery_branch_review still independently judges
the complete actual candidate after real Check. Verifiable early analysis may
reduce repeated reading; it never supplies a formal final pass.


## Actual Candidate Set

Complete the selected profile's semantic review before forming the actual
candidate set. When that complete review finds no real candidate, record
`candidate_classifications=[]` and invoke none of the three nonempty-only
qualification owners. Do not invent a no-defect candidate from a reviewed file,
feature, or a passing check. An empty set does not establish `passed`,
`continuity_passed`, or `archived_review_passed`: every applicable entry,
Architecture, Docs, range, dimension, evidence, freshness and route condition
still applies. Bounded continuity remains bounded and archived review read-only.

When real candidates exist, invoke the existing normal-scenario and
solution-mechanism owners, then root-cause qualification for eligible refs,
using `branch_review_candidate_set`. Keep every actual terminal classification,
witness and semantic disposition. Nonempty all-rejected candidates are distinct
from no candidates. Every finding, proposal, observation, follow-up and rejected
candidate still binds a classified ref; an empty set cannot carry such a row.

## Archived Read-Only Review

Use the independent `delivery_archived_review` input with exact archive
Task locator, public Delivery key, content HEAD and live PR payload snapshot.
It requires actual current-generation Completion/Closure and committed archive
summary/Delivery plans. It consumes no current Check and writes no active gate.

Resolve the selected Delivery's actual fixed content base B before reviewing;
for a legacy/stopped candidate without that anchor, the original range owner
selects the unique merge base once and pins it in this owner's checkpoint.
Live GitHub target identity is separate. Do not fetch, synchronize, or update refs.
The global workflow owns the fresh Architecture
`delivery_task_impact_sync(stage=branch_review)` invocation with
`source_exit=review_refresh_required` over exact B..A. Consume only its
read-only accepted result; missing evidence, blocked, or a result requiring
promotion/repair stops, never enters a writable consumer.

Independently review the full current B..A diff, live requirement authority,
archived planning and current test evidence. Neither the prior review nor a
PR snapshot is a semantic pass. This profile overrides ordinary finding-fix
and scope routes: content findings, scope insufficiency and missing authority
return only `blocked`, retaining truthful current findings in the private
semantic result. Do not restore tasks, fix content, rewrite archive history,
promote Architecture, update PRs, or mutate Issues.

After fresh AI review, use the same review-branch/check-review-gate/invoke
commands. The dedicated closed `archived-1.0` gate admits only
`archived_review_passed|blocked`; it is never synthesized from an ordinary
checkpoint. Both exits retire the owner checkpoint after validated projection.
The success output carries only task_ref, A, the exact title/body snapshot,
delivery_key and reviewed_base_head B. In the current graph this archived-review result
stops for pinned-old or manual disposition; it does not feed Delivery Review.
Changed A/content-B/PR payload, non-Ready
state, dirty archive or mismatched archive Task/summary identity fail closed without repair.

## Ordinary Reviews

Before searching the range, Docs, tests, fixtures, consumers, or relevant
history, read `.trellis/spec/workflow/semantic-retrieval.md` and apply it in
candidate qualification. A negative finding or impact conclusion cannot rely
on a single-language zero result, and no query process enters the gate or DTO.

Validate all eight entry preconditions in workflow or standalone mode. Perform one
independent semantic review of the complete current range. When real candidates exist, form only candidate
refs and live locators, then invoke `guru-qualify-normal-scenario` with
`branch_review_candidate_set` before assigning severity.
For delete, replace, merge, or compatibility-impacting ranges, apply
`.trellis/spec/workflow/subtraction-first-compatibility.md`: independently
recompute `code_subtraction` and `docs_ssot_subtraction`, verify deprecated-asset
exit and direct evolution, and treat unsupported compatibility or redundant
growth as a finding. Do not use Phase 2 evidence or a generic continuation as
compatibility approval.
Independently review long-term maintainability as well: consume the contract's
Current constitution consumption and Architecture's adopted-mechanism review
through the existing qualification and revision owners.
Excluded threat, concurrency, crash, or formal idempotency concerns do not
justify additions. Every touched non-generated code file at or above 3000
lines requires a mechanical-split or small-decoupling conclusion; untouched
historical large files are not imported into scope.
Immediately before dispatch, tell the user in the current dialogue the
independent reviewer identity, the exact committed `base_oid..head_oid`
range, and the review target. Immediately after return, show the final finding
summary and the semantic owner's conclusion. Keep the reviewer transcript and
these lifecycle notices dialogue-local; do not persist them in a gate, DTO,
checkpoint, or tracked report.
Scripts never decide scope, scenario class, qualification, severity,
review sufficiency, pass, or route.
Rejected candidates remain `rejected_candidate` without severity or
finding-only fields and cannot become scope confirmation, tests,
implementation, follow-up, or publication blockers. Mechanism revision returns
to task work for remove/replace and fresh qualification; blocked stops. The
review gate records only this owner's final classifications and direct-consumer
witness, never a qualification artifact.

For a real candidate, before a proposed review mechanism participates in severity, findings, scope,
or blocker judgment, invoke `guru-qualify-solution-mechanism` with
`branch_review_candidate_set`. A `mechanism_revision_required` result removes
or replaces only that mechanism and returns to task work for fresh
qualification; it never enters scope confirmation.

Before this review can pass, consume a fresh
`guru-maintain-architecture-baseline:delivery_task_impact_sync(stage=branch_review)`
result. The Architecture owner independently recomputes project checks and
before/after satisfaction from the complete committed base-to-HEAD diff. This
Skill then rereads the current Architecture Baseline, design constitution, and
task-local change contract as part of its own complete-range semantic review.
Neither owner may reuse the Phase 2 Architecture result as Branch Review proof.
For engineering commands, follow the contract's Engineering validation in the
complete review: determine the current complete check set first, judge accessible
original facts independently, document execution/adoption and sources, and
execute affected or new checks. This never substitutes for current semantic
review or exact-range result binding.
A single extra blank line, or multiple blank lines, at the end of a text file
is formatting noise when it is the only observed issue and the file's
meaningful bytes are otherwise unchanged. Keep EOF-only whitespace as a
non-blocking observation; it must not become a qualified P0-P3 finding or an
`implementation_required` route. This narrow rule does not suppress trailing
spaces on non-blank lines, indentation changes, changes inside
strings/configuration values, invalid encoding, or whitespace that changes a
parser/linter/formatter contract.
A stale identity, incomplete contract, authority conflict, fitness regression,
unreviewed contribution, or missing project check prevents `passed` and follows
the Architecture result's unique global route.

Every official independent-review worker invocation prompt authorizes
approved-plan work only. A planning-external observation must stop before any
edit, added test, self-fix, severity, classification, or route and return only
`candidate_ref`, `observed_behavior`, `locators`, and
`minimal_reproduction_hint`. This owner rereads the live range and authority
and completes fresh qualification before continuing the review or dispatching
another worker for that candidate. Upstream-owned `trellis-*` agent files stay
unchanged.

Current-scope qualified findings return `implementation_required`; fixes must
pass the applicable checks, a fresh task commit, and this Skill again. An
unconfirmed nonstandard proposal returns `scope_confirmation_required` and
cannot become a finding. After a fix commit, the finding owner or a real
unfinished-agent replacement performs closure as an internal transient
judgment. It retains `introduced_head`, binds the fixing `fix_head`, and
produces a later `closure_head` plus concrete closure evidence. The AI workflow
then reviews the complete current `base_oid..head_oid` coverage under the
shared candidate contract. The same compliant independent reviewer may continue;
review closure, the entire fix delta and affected dependencies, supplementing
missing coverage or performing the complete review when impact is unbounded.

Closure emits no public exit and writes no artifact. Only the actual current
final judgment with `review_intent=fresh_final_review` may reach the recorder
and pass. MIGRATION-637 defines this wire value's successor meaning; closure
alone is not passed. After its AI Review Gate
exists, the recorder writes the compact `review-gate.json` to the exact
task-owned ignored-runtime checkpoint and returns only a minimal receipt; it
does not create assignment, liveness, rollup, or raw per-round reports. Only
after `check-review-gate` resolves and validates that exact checkpoint
may the public wrapper emit exactly one of `passed`,
`continuity_passed`, `implementation_required`,
`scope_confirmation_required`, or `blocked`.
The checker is not a public pass: it returns
`status=owner_checkpoint_validated` with `formal_exit=false`. Only the public
wrapper's DTO is a formal Branch Review exit.
The semantic owner's passing conclusion is provisional. Do not tell the user
that Branch Review has formally passed until both `check-review-gate` and the
public wrapper return `passed` for the same current task, range, commit, and
reviewed-content identity.
`continuity_passed` is only a bounded continuity judgment over a previously
reviewed task plus one committed reconciliation pair. It must never be
described as a full Branch Review.
`passed` targets `guru-review-task-delivery` through its target-owned authoring
seed. The workflow caller supplies current Delivery policy and live PR facts
before invoking that owner.
This package is not self-contained or portable.

The public wrapper accepts only current public input, reruns the objective
checker internally, and never accepts caller-authored gate or checker output.
Successful `passed`, `continuity_passed`, and zero-payload stop `blocked`
projection retires the checkpoint. The two active re-entry routes retain the
one checkpoint for deterministic
same-owner re-entry; a repeated invocation returns the same DTO without writing
another checkpoint. Failed check or projection preserves the current regular
checkpoint. A retired, mismatched, stale, unsafe, or symlink-backed checkpoint
fails closed.

Required Architecture promotion happens before final Check. The committed
Architecture review and this independent complete-range Branch Review cover
actual promotion files and before/after responsibilities. A later change
returns to the earliest affected owner according to its actual obligations.
For the bounded exception after an actual complete Review, use
`delivery_promotion_reference_alignment` exactly as defined in the contract's
Promotion reference alignment section. It emits the existing `passed` only
after the original owner reviews all Git delta and affected dependencies.
Delivery Review consumes the new current full_review; it never substitutes a
Phase 2 result or relabels the old pass.

The current Delivery aggregate dispatches independent full Review, continuity,
archived Review and promotion reference alignment profiles. Full Review and continuity bind the exact actual Check,
current candidate and base. The full Review gate writes only after independent
review. Continuity separates prior full-review HEAD from current committed
integration HEAD/tree and never creates a new full Review result. Checkpoints
are scoped by public Delivery UUID. Their legacy schemas serve historical
inventory only, never a current development fallback.

For a nonempty actual candidate set at this boundary, consume actual normal-scenario and solution-mechanism
outcomes before loading `guru-qualify-root-cause` with `branch_review_candidate_set`. Supply only eligible
refs. New or materially changed incident/protection mechanisms enter that owner;
ordinary features receive its stable applicability disposition. Consume a
still-applicable same-mechanism conclusion on later stages and independently
review this stage's current work/evidence; caller change alone does not repeat

## Current-stage scope revision

`delivery_scope_revision` is this existing owner's semantic re-entry after original
Clarify has published the changed whole-Task scope. Read actual accepted scope,
selected Delivery and obligations; review the retained slice anchors and original
source_selection/revision_refs. Complete the AI gate before invoking this profile.
Do not require stale Planning/Check/Review/Readiness evidence to revise scope.
Project only the reviewed current scope_ref through upstream rework to planning;
invalidate planning/check/full_review/readiness and retain identity, candidate and
historical publication/delivery facts. No new acceptance or approval is inferred.
`delivery_scope_revised` goes only to guru-delivery-scope-revised-router and the
same Delivery Author active_task_scope_change. A retry after lost output reads
matching public scope, planning phase and cleared results; it returns the same
minimal handoff, without replaying rework or installing an approval token.
A new change receives fresh original Clarify and this owner judgment.
