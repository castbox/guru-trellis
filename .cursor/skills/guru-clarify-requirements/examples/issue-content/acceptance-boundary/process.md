# 分页组件与 CLI：验收边界和证据去重

这是合成的去敏教学场景，不是实际 Agent 执行记录、当前 Issue 或通过结果。方法只由[共同内容规范](../../../references/issue-content.md)和同一 provider 的 `quality-guidelines.md#test-and-validation-value` 定义。

## 有效来源与混合草稿

有效来源确认三个独立结果：库调用方通过分页组件取得约定结果；维护者通过随组件发布的 CLI 取得同样结果；分页配置发布命令更新业务配置并返回 revision。CLI 调用组件的接线明确属于本次交付。来源还明确要求 CLI 在目标 runtime 4.2 读取既有配置，因为该兼容承诺只能由目标环境判断。外部业务应用的接入、页面、服务版本部署和上线由其 owner 承担。

来源还明确：保留记录顺序、完整 total、现有字段与异常类型；非法 offset/limit 必须在 `source.load()` 前拒绝；合法请求只加载一次。这些技术条件不能因结果通过代码或内部状态观察而删除。

待整理的草稿把下列内容并列为验收：

- 分页组件返回有序切片、完整 total 和约定错误。
- CLI 输出同样结果并实际调用分页组件；另建创建、复审和验证方法三个场景重复证明该行为。
- 单元、集成、E2E 和联合验收分别再次证明同一分页结果。
- 每层测试通过、编译与静态检查通过、达到新增覆盖率门槛。
- 每个 Issue 部署共享 test 环境；业务“发布分页配置”因名称含发布而要求部署服务版本。
- 为确保万无一失，消费方业务应用完成页面 E2E 和生产采用；未接入时暂不完成组件 Issue。

重复 CLI 场景可以归属分页目标，但目标归属不足以证明它们有独立验收价值。测试层级和覆盖率项混合支撑证据与无来源门槛。共享环境、服务部署和消费方 E2E 项跨出当前责任边界。目标 runtime 4.2 是实现既有兼容承诺所必需的条件，不能随这些扩张一起删除。

## 整理后的完整教学正文

### 背景与目标

为库调用方交付分页合同，为维护者交付随组件发布的 CLI 和分页配置发布命令。当前 Issue 包含 CLI 到组件的接线以及目标 runtime 4.2 的兼容结果；不承担消费方业务应用的接入、页面、服务版本部署或上线。

### 行为与兼容

`page(source, offset, limit)` 返回有序切片和全部记录的 total。offset 为非负整数，limit 为正整数。非法参数返回现有 `InvalidPage`，且在调用 `source.load()` 前拒绝；合法请求只加载一次。保留现有导出函数、结果字段和异常类型。

CLI 接受同样参数并调用本组件，输出 items/total JSON。参数错误返回非零退出码。CLI 接线是来源明确包含的联合交付。

`publish-pagination-config --config <path>` 更新指定路径中的分页业务配置并输出 revision。它是业务配置操作，不部署服务版本。

### 可观察验收

1. 库调用方通过组件入口取得正确的有序切片、完整 total 和约定失败结果，并满足上述加载时机、次数及兼容合同。
2. 维护者在目标 runtime 4.2 通过 CLI 取得同样的分页结果和参数错误表现，CLI 实际调用本次组件并从指定路径读取既有配置。
3. 维护者执行分页配置发布命令后，目标配置得到约定更新并返回 revision；该结果不要求服务版本部署。

### 来源与未决项

来源是本例开头的两个目标及明确技术条件。没有未决产品选择；具体测试组织由原规划和验证 owner 决定。正文是待验证要求，不表示组件或 CLI 已实现。

## 证据如何承接

假设已有组件入口观察证明切片、顺序、total 和参数错误；已有 CLI 观察证明其实际调用组件及输出。这些证据的对象、条件和路径仍适用时，可以复用。换 reviewer 或进入下一阶段不自动要求重跑，也不要求内部各层重复相同结果。

外部参数错误不能单独证明“在 source.load 前拒绝”。若已有记录没有观察加载时机与次数，只补真实组件入口的定向观察，例如统计边界外 source 替身的调用次数。替身提供数据和记录调用，分页结果仍由被测组件产生。该观察支撑原承诺，不另建第三层验收。

明确属于本次的 CLI 接线仍须有相应证据。目标 runtime 4.2 的兼容结果也须在目标环境实际观察；部署分页组件服务或共享 test 环境不能替代这项检查。删除消费方 E2E 不等于删除来源已经要求的联合交付或目标环境承诺。配置发布命令的真相、配置更新和 revision 结果由业务操作自身证明，不据此追加服务部署。编译、静态检查或其他验证只有存在当前独立价值时由原职责采用，不能因为从验收移出就默认全部变成后续必做项。

## 后续审核与写入边界

若下一轮普通意见要求恢复页面 E2E、共享 test 部署、服务发布、逐层重复验收，或将它们改名为风险、必要保护、强制 follow-up，原 owner 在本轮输出前核对有效来源和已有覆盖。依据不成立时删除候选及其阻塞后果。内部加载承诺、明确联合交付和目标 runtime 4.2 的真实证据缺口仍保留定向补证。创建、复审和验证方法对同一 CLI 行为使用一个代表性场景观察，除非存在不同结果或风险。
