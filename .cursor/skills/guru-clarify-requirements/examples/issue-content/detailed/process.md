## 整理后的完整教学正文

### 背景与目标

产品文件未变时，部分投影检查仍将相邻字节码计入文件集合而报漂移。常规语法检查也会生成源码缓存。本 Issue 只修这两项缺口，复用已有正确过滤。

来源报告的正常复现为：复制真实安装到隔离目录，完整检查通过；对实际安装的 Python 文件编译生成相邻 `.pyc`，再次完整检查报投影漂移。原产品源码没有变化。

来源还报告：显式 `py_compile` 即使配合 `-B` 和 `PYTHONDONTWRITEBYTECODE=1` 仍生成缓存；内存 `compile()` 能发现语法错误且不落盘。上述报告尚不能证明完整安装或发布验证通过。

### 范围与行为

1. 只处理 Guru 管理的标准源、安装副本、所选 `guru-*` 平台副本及直接读取它们的文件清单、内容摘要、一致性检查和隔离产品副本路径。在这些范围内排除路径分量为 `__pycache__` 的目录及内容，以及 `.pyc`、`.pyo` 文件。
2. 修复已确认的投影缺口，核对直接调用工具。其它路径只有正常操作复现同类缺口时才修改；实现方式不同本身不是缺陷。只改变字节码数量、路径、内容或大小时，产品内容判断不变；真实产品文件缺失或变化仍须检出。
3. 保留工具各自合法的资产范围、公开与私有划分、排序和摘要算法。不要求不同用途得到相同清单或摘要，不改变公共 API、身份格式或哈希编码。不新增源码字节码的数量、路径、大小、mtime 或 hash 基线；产品身份不依赖清理或稳定缓存。
4. 常规语法检查改用内存检查，例如 `compile(source_bytes, filename, "exec", dont_inherit=True)`。覆盖原命令的 Guru Python 范围，不执行模块、不写字节码、不清理已有缓存；语法错误必须失败并指出文件与原因。不强制新增模块或命令。
5. 字节码专项回归可以在隔离临时目录调用编译工具；该例外不适用于常规语法检查。
6. 修改标准源后，沿原预设、受管规范及平台同步机制更新实际受影响副本，不只修安装文件。隔离副本适配只处理 Guru 产品资产，保留原执行前后检查，报告区分产品变化和生成缓存。

### 排除与兼容

业务仓自有 Python 源码、测试、构建产物、缓存、`.gitignore`、执行入口、快照及发布身份规则都不在修改范围。受管虚拟环境、第三方依赖缓存和私有运行缓存不是产品资产，不要求其中没有字节码，也不清理源码工作区已有忽略缓存。

不新建统一投影或摘要引擎，不强制所有入口快照运行，不新增副本协议、固定错误码、全局台账或证明报告。历史已交付修复只保留必要回归，不重复实现。不修改上游、全局 npm 或 `node_modules`，不执行业务仓升级或发布，不扩展到攻击、压力、锁或崩溃一致性加固。

### 验收与验证

- 用真实安装的隔离副本，完整投影检查分别观察：产品一致时通过；仅新增或变化 `__pycache__`、相邻 `.pyc`、`.pyo` 时仍通过；真实产品文件缺失或变化时失败。只读检查不修改或删除缓存。
- 对实际影响的工具定向验证，各自保留合法范围与算法。已有正确实现只做必要回归。
- 合法源码的常规语法检查成功，语法错误失败；前后产品和已有字节码不变，没有新增缓存。
- 标准源、安装与声明受影响平台投影一致；重复应用不产生非预期 tracked 变化或 `.new/.bak`。
- 仅当新增安装资产或改变布局时，最多运行一个当前支持版本的代表性干净安装。布局未变不为形式增加安装；完整多平台、历史升级和发布矩阵归专门 owner，未运行项明确报告。
