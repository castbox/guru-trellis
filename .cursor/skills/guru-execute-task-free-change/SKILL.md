## Qualification Applicability

At this Skill's candidate boundary, first read the original owners' short
[normal](../guru-qualify-normal-scenario/references/applicability.md),
[solution](../guru-qualify-solution-mechanism/references/applicability.md), and
[root](../guru-qualify-root-cause/references/applicability.md) conditions before
loading any qualifier in full. This owner judges each condition independently
from current authority, actual candidates and material changes; it does not
copy a qualifier's complete verdict. Adopt a still-applicable conclusion. Only
when an owner's conditions require a current invocation, explicitly load that
stable Skill and invoke it with its real applicable nonempty set and the
profile below. If it does not trigger, load no qualifier body, assemble no
input and emit no empty, classified or skipped result for it. The complete
current-stage judgment and all applicable non-passing routes remain required.

Read `.trellis/spec/workflow/workflow-contract.md#interaction-budget` before
any confirmation, choice or clarification. This Skill retains its own action
plan, confirmation boundary and execution/recovery contract.

Invoke this Skill only after `guru-select-workflow-mode:task_free`. The caller
authors the current request summary, bounded target paths, continuation identity,
and whether selection was automatic or explicit. The selector contributes only
its existing `exit_id`; checkout facts never enter the selector DTO.

The AI owns the complete semantic loop: read local checkout/task/dirty facts,
judge write suitability, perform only the bounded edit, run risk-matched targeted
checks, and review scope/risk again after writing. Scripts only validate the
AI-authored result and serialize one typed exit. Never query branch protection.

Before the pre-write suitability decision, apply Qualification Applicability.
If normal requires a current invocation, form only its actual candidate refs
and live locators, then invoke `guru-qualify-normal-scenario` with
`task_free_pre_write`. If execution discovers a new behavior, scope, test, or
risk candidate, stop further target writes and apply the conditions again;
invoke it with `task_free_evolution` when required before deciding expansion
significance or route. Consume only an actual current result when invoked: classified candidates return to this owner,
scope-confirmation candidates go to requirements clarification, mechanism
revision returns here for remove/replace and fresh qualification, and blocked
stops. Rejected candidates never become a user question, test, implementation,
or risk-expansion route. Qualification decisions remain invocation-local.

At each of those candidate boundaries, apply solution's own conditions.
When they require a current invocation, explicitly load and invoke
`guru-qualify-solution-mechanism` with the same profile before accepting a
proposed mechanism as part of the task-free edit or evolution decision. Its
`mechanism_revision_required` exit removes or replaces only the proposed
mechanism and returns here for fresh qualification; it never enters scope
confirmation.

`completed` requires current evidence for both the pre-write suitability review
and the post-write scope/risk review, plus the actual edited paths and targeted
checks. Its workflow output reports edited paths, concise validation results,
and unverified boundaries.

`reselect_mode` and `explicit_choice_required` require evidence of the actual
partial edit, the discovered scope/risk expansion, immediate write stop,
remaining target writes not performed, and applicable targeted checks. Neither
mode selection nor an exit authorizes commit, push, PR, merge, release, installation, cleanup, Issue
closure, or Task creation/activation/binding. Worktree/branch acquisition is this
owner's pre-write location action with its own exact authorization, never a
Task lifecycle operation.

New AI-generated locations consume the primary project's configured
`worktree_root` through the public environment precheck before ordinary Git
creation. Genuine explicit locations and suitable existing checkouts keep
their own location rules; the generated root is not an allowlist.

Read [references/contract.md](references/contract.md) before location selection
or editing, including first-write isolation, continuation and partial-edit
carryover boundaries. A read-only turn creates no resources.

Return exactly one of `completed`, `resume_active_task`, `scope_change`,
`location_required`, `reselect_mode`, `explicit_choice_required`, or `blocked`.
`location_required` and `explicit_choice_required` re-enter this Skill after the
dialogue-local choice. Preserve unrelated dirty and untracked work.


At this candidate boundary, apply the original
[root conditions](../guru-qualify-root-cause/references/applicability.md).
When they require a current invocation, explicitly load `guru-qualify-root-cause`
with `task_free_pre_write` / `task_free_evolution` and supply only actual eligible refs. This caller uses its
current scenario and authority-placement judgments and consumes actual normal
or solution outcomes when those owners triggered. It never requires an outcome
from an owner that correctly did not trigger. Adopt a still-applicable
same-mechanism conclusion and independently review this stage's current
work/evidence; stage or caller change alone does not repeat qualification.
Material changes refresh only affected judgments; a lost necessary conclusion
returns to its original owner for recovery or fresh judgment. Root `classified`
continues this stage, retaining diagnosis or mitigation disposition without
claiming repair. `mechanism_revision_required` removes/replaces that mechanism
and reenters; `diagnosis_required` pauses only the unsupported repair and
continues bounded investigation of the returned gaps through this owner, then
resubmits. A concrete `blocked` stops. Do not turn symptom suppression into
unrelated scope confirmation, cache qualifications, or use qualification as
completion. Actual scope changes use existing routes.
