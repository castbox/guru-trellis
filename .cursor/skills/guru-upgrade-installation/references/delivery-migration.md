# Delivery installation migration

`judgment_mode=semantic`. The new `delivery_upgrade`, `delivery_resume` and
`delivery_rollback` inputs are independent of the historical Plan1 profiles.
Plan1 is a historical migration consumer, never a current Delivery runtime
fallback. Use this complete source-loaded owner, not the old installed dispatcher.

Before writes, read actual versions, original receipts, every registered
workspace, occupied active/archive root, common/local session, task artifact and
original private transaction. Normal old archives and same-version schema
cutovers remain supported. Unknown versions/malformed projections stop without
writing. Historical successes are facts; old gate passes are not current passes.

Use `preview.sh` with `delivery_upgrade` and the fixed installed CLI entrypoint.
Without a plan it returns the actual complete Guru source HEAD/bytes/modes,
installed CLI/Core bytes/modes and prospective templates. The owner builds the
exact upstream Plan2 using `collectMigration2Templates` and
`migration2TemplateCandidate`; custom workflow uses `template_id=guru-team` and
the actual declaration/content, never a bundled native receipt claim.
With a plan the preview calls `validateTaskV2Projection` and upstream `migrate2`
dry-run. Source preconditions are prospective, not ordinary post-install apply.
Upstream exclusively owns its task/session/schema and full-inventory algorithms.

The plan-free preview also returns a call-local raw inventory: every eligible
registered project root and its actual branch, occupied active/archive directory
(including a missing historical task record), Task/artifact bytes and modes,
workflow/receipt/extension preimages, and common/local session preimages. It
does not select conversion dispositions. For each observed active identity with
an existing common-dir C4 binding, it reads that original binding and returns
the upstream `branch_bindings` row with only `task_id`,
`lifecycle_generation`, and `source`. Include unique active Tasks as well as
inherited copies. Git-free inputs have no branch-binding rows. Do not scan
unrelated binding histories, create a binding, or put a target path/new branch
into this projection.

Plan2 `workspace.root` already identifies the project root, including a
monorepo subdirectory. `project_relative` locates that project beneath its
registered Git worktree top; never append it to `root` again. Guru preset,
private-owner calls, backups and rollback use that exact public project root.

Using the actual original binding and checkout facts, the semantic owner chooses
one projected active authority and preserves inherited active peers with
`defer`. Submit all roots, original Task sources, per-branch planning and session
rows without merging mutable planning. The installed public Plan2 executor
alone validates immutable-source/generation agreement, group legality, binding
freshness and its unique actual checkout. A deferred peer receives no Delivery,
migration artifact or Guru private-owner conversion; private calls must belong
to a projected Task in their selected workspace. Normal source, binding or
registration changes return to fresh prepare rather than changing the frozen
plan or extending rollback anchors. Older closed-schema CLI candidates cannot
consume `branch_bindings`; acquire the reviewed matching candidate and fresh
prepare, keeping earlier plans with their original packages for same-plan
recovery. Same version numbers do not establish package equality.

The private Plan2 package plan contains the full upstream `core_plan`, frozen
`source_candidate`/`fork_candidate`, per-workspace platform/Guru asset decisions,
exact private controls, and original-owner migration calls. Every private call
names its registered private command, real input, original semantic `owner_result`
and bounded write paths;
Upgrade never creates that owner's pass or determines cycle/Delivery attribution.
Original private wrappers emit intermediate receipts, not new formal exits.
TaskCommit owns committed planning blob provenance; Publish/Merge own their
same-plan transaction associations. Unconvertible gates stay historical and
reenter their original owner. No second Delivery authority or permanent cycle map.

AI reviews the complete dry-run writes/preservation/removals, source frozen
identity, every private owner result, installed platforms, session disposition
and backups. Show the exact targets and obtain current-dialogue confirmation
only for real choices or target writes. Never serialize authorization. Controlled
local_candidate rehearsals freeze actual managed source bytes/modes and both
installed packages; they report formal_fork_source_lock unverified. Formal
source_locked additionally requires clean committed Guru source, the original
fixed source-lock validation and installed dist equality with its exact build.
Dirty HEAD/version alone cannot identify a formal source.

The executor first backs up all upstream absolute actions, all per-workspace
Guru/preset/sidecar paths and private-owner write paths/control files, with raw
bytes and modes. It then executes the same upstream Plan2, the original private
owners, retirement of exact old Guru-managed bytes, complete preset and actual
activated installed validation. After Core creates the target projection, each
original private owner first
returns its read-only preview. Its actual write paths must fit the initial
reviewed paths and frozen backup before that owner writes. A missing path stops
for same-owner reentry without extending backups or refreshing rollback anchors.
Nonterminal Merge history remains a fresh-Merge-review route with no private
write or current gate pass.
A partial operation returns delivery_resume. Retry consumes the same schema2
checkpoint/plan and never re-freezes sources or
rollback anchors. Its original business snapshot also binds the registered
worktree paths/branch-or-detached routing and each planned project's actual
checkout branch. Resume and rollback check the same fixed snapshot even after
Core has completed; normal registration or same-HEAD branch changes stop before
another private/preset write or restore. A checkpoint without those original
routing facts cannot be refreshed to make it resumable. Lock/prunable descriptions
are not routing facts. Third-state changes stop and remain untouched. Missing private
owner result returns to that owner; independent task/Delivery work is not erased.

The original Git-private checkpoint remains solely for rollback and retained
history diagnosis during reapply. Exact Plan2 defer/history_only preimages are
accepted as historical records under the matching API1/schema2 declaration;
they never enter lifecycle/session selection or provide gate authority. Retire
that diagnostic consumer only after its retained records are retired or migrated.
Backup cleanup is not an implicit upgrade action.

Rollback is a separate semantic action. Review newer business/task/session/
archive/control work first. The executor checks the full managed postimage and
fixed pre-write business/topology tokens; newer work blocks restore. It restores
all workspace and common/local session raw bytes/modes, removes only newly
created migration files and retires the consumed backup. It never resets Git,
rewinds commits or alters remote PRs. Read back old runtime and preservation
facts before reporting rolled_back. Installation success, each task's fresh
owner gates, joint validation and original business-session recovery are four
distinct outcomes; neither upgraded nor test fixtures imply the other three.
