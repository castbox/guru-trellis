# #793：qualifier 条件加载与调用

## 变化与不变合同

本次窄替代十类 lifecycle 边界及已有 `author_candidate_set` 中固定
normal/solution 调用，以及 root 一律要求两个实际上游结果的前置。
每个原 qualifier 以自身 `references/applicability.md` 拥有可先读取的条件。
caller 读取短条件后判断触发、采用或刷新；触发且无仍适用结论时，显式
加载原 stable Skill 并完成其原语义闭环。caller 的轻量判断不替代资格 verdict。

未触发不加载全文、不装配空输入、不制造 `classified`、empty 或 skipped
输出。root 接受 caller 当前场景和 authority-placement 判断；normal/solution
实际触发时必须消费其真实结果，正确未触发时没有这些结果前置。真实新建或
实质改变的诊断、缓解、修复、保护仍进入 root，不能靠名称改成普通功能。

三个原 Skill id、profiles、public input/schema、命令、typed exits、输出投影和
唯一 consumers 保持。未改变资格算法或生命周期。新短条件沿原 package
`references/` 投影分发，Interface 用既有入口说明定位，不新增字段、wrapper、
脚本 classifier、资格台账或授权存储。

## 完整采用与在途接续

成套采用 canonical workflow、三个 qualifier、实际 caller/consumer、必要 spec
和声明平台投影。不能只删除 global mandatory 或复制短条件后继续旧 root/caller
前置。旧完整安装在采用前执行其原合同；已有 checkout 保 Task/session 的工具
同步由原 `guru-upgrade-tools` 从完整匹配源执行，完整安装迁移仍归原 owner。
保留用户修改，按原机制处理 `.new/.bak`，读取实际安装并验证投影与 drift。

同 Task/generation、DeliveryKey/planning_root 和当前阶段续接。当前合法规划、
实现、Check、Review、发布及恢复职责仍须完成。既有真实结论在对象、authority、
机制、条件和证据仍适用时采用；阶段/caller 或无关字节变化不单独要求重跑。
实质材料变化只刷新依赖判断，丢失必要结论由原 producer 恢复或重新判断。
新正式调用仍通过当前 facts/schema/freshness 校验，不重放旧 invocation envelope。
没有持久数据格式迁移、旧结果 reader 或新旧双写层。

## 出口与验证边界

拒绝项不提升为 scope、测试、finding 或 blocker；机制修订回原 owner 删除/替换，
诊断回原 owner 有界取证；真实范围选择进入原 Clarify，blocked 使用原 stop。
未知、多重或 unmapped 出口保持 fail closed。脚本成功不证明语义通过，资格
结论也不证明本阶段或 Task 完成。

针对实际改变 caller/consumer 验证未触发、真实触发与非通过承接、采用、
材料变化刷新、结论丢失恢复，以及受管投影。采用仍适用证据，补实际缺口，
区分确定性 wrapper、实际 Agent 行为与安装观察。不要求全阶段乘积、固定案例
数量、业务事故重放、费用比例、通用评测框架或完整多平台安装矩阵。
