# 验证仓设计宪章

版本：531-validation-constitution-1。状态：current。原 Architecture foundation owner 已对下列原则在此仓职责与最小机制上的适用性完成审查。仅约束此远端恢复验证仓。

- mature-practice-applicability / 成熟实践与适用性：使用已安装且与此样本兼容的原 Publish/Merge 入口；真实 GitHub 行为须由实际执行证据证明。
- concept-semantic-completeness / 概念与语义完整性：区分 Task、Delivery、publication fact、merge fact 与整体 Completion；历史成功不能解释为当前门禁通过。
- cohesion-change-isolation / 职责内聚与变化隔离：上游拥有公共状态与转换，原 Publish/Merge 拥有各自事务；样本不建立第二 owner。
- minimum-necessary-complexity / 最小必要复杂度：一个 txt 和必要规划/foundation 足以承载验证；不添加业务应用、ledger 或新恢复机制。
- debt-one-way-convergence / 技术债务单向收敛：缺失证据保持明确 GAP；版本变化重新验证，不以重试或旧 fixture pass 填补真实证据。

原则用于整体设计判断，不按分值或逐项机械 pass 建立审查结论。权威导航见 ../README.md。
