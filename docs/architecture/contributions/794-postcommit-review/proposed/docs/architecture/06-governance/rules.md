# GOVERNANCE

- `ARCH-GOV-001`：Architecture 变化按 `bootstrap_foundation`、`task_impact_sync`、`promotion` 或 `repair` 进入唯一 semantic owner。
- `ARCH-GOV-002`：CURRENT 条目必须有 current code/config/test/release evidence；`inferred`/`unverified` 不能晋升为 CURRENT。
- `ARCH-GOV-003`：每次 gate 读取 live authority，由原语义 owner 选择并重读明确阶段适用的 locator/version/status 与真实 task delta。无关整体 CURRENT/ref/version 前进不改变已选适用性；真实立即适用规则变化须明确对象和承接要求并回原 owner。unknown/multiple/真正 stale exit 继续 fail closed；ADR-028 定义固定内容边界；ADR-034 定义后继候选原覆盖、差额及受影响依赖的适用性。首次完整独立和当前正式结果保留，HEAD/阶段/reviewer 身份本身不要求相同全量重做。
- `ARCH-GOV-004`：Architecture/RDT/projection 三者 locator 与 traceability 必须一致；projection 只能包含读取规则、identity 与 freshness。
- `ARCH-GOV-005`：普通并行 task 使用隔离 contribution，不共同写 shared current；这是 ownership 规则，不引入锁、TOCTOU 或共享协调状态。
- `ARCH-GOV-006`：每个标准 task mandatory 进入 Architecture semantic owner；`architecture_impact` 恰好选择 `target_native`、`legacy_boundary_convergence` 或 `dedicated_refactor_slice`，`no_architecture_impact` 只返回 current identity 与可审核理由。
- `ARCH-GOV-007`：Guru public identity 与项目 baseline/change-contract identity 只在 task-local Architecture change contract 相交。明确阶段适用的 concern、owner、GAP、before/after、project check、evidence、review 或 freshness 缺失、过期或冲突时 fail closed。digest/ref 只服务本地事实一致性；无关整体版本推进不代替适用性判断，也不使旧 pass 自动适用于真实新候选。
- `ARCH-GOV-008`：普通 Task 先写隔离 contribution 与完整 proposed 正文。批准 Planning、完整实现和真实工程结果支持原 maintenance owners 在提交前 final_integration 整合；不要求 candidate Check 或提交前独立 implementation Architecture pass。原 owners 固定真实目标，比较 applicable before、双方 proposal、实际 current 及必要 consumers，保全部有效条件，写入/readback并判断实际适用性。Architecture integrated_pending_review 只证明整合；TaskCommit 纳入全部 after。implementation 以固定 B/H 和完整 paths 绑定 committed candidate，新的独立 reviewer 先读 before authority，再审 after/consumers，形成一次 Architecture before/after 和九维/完整 Review。真实通过后顺序写 check/full_review；只有实际整合和该独立判断都完成才是 reviewed_promoted，pending 不得 readiness/Publication/Finish。no_change 无空贡献/ADR/commit。single-writer、expected-current、稳定 identity、partial/output-loss 同 intent 恢复保持；真实冲突或 intent 不唯一停止。当前时机由 ADR-POSTCOMMIT-INDEPENDENT-REVIEW 窄替代旧重复 Check，原历史与真实 API 版本保持。
- `ARCH-GOV-009`：Delivery Review 判断当前 slice 与真实 PR readiness；Publish 拥有独立审核/readiness后的同 PR 发布、最终 Ready及其事务恢复；审核前新 push/PR 禁止，旧 Draft 仅按 MIGRATION-794 恢复已执行事实或在当前资格后补 pending；早期反馈不证明最终 gate，Merge 核验 live eligibility、expected-head 和实际合并结果，并通过当前 Interface 的正式出口接续。每个 Delivery PR 只使用 `Refs`，合并不关闭整体 Task 或 source Issue。Completion 独立判断全部 accepted scope 和实际 Delivery/证据；Closure 随后独占 exact-source Issue disposition，可按当前合同冻结关闭或保留 open 的动作。Closure 仅将不可重新推导的最小动作集合写入 task-local 共享载体并关联原公共结果；载体不记录授权或 terminal pass。Finish 经公共结果/AuthorityRef 读取精确动作集，逐 Issue 核当前 required 状态后归档/bookkeeping，Cleanup 独占资源删除。已成立的共享 Finish 不以原机 seal、binding 退出或 Cleanup 为准入前提，本机责任继续归原资源 owner。Publish 的精确 Open PR 恢复与 Closure 的共享结果恢复只补已发生动作，仍由原 owner 重判当前资格，不重复创建、合并或关闭。其他 owner 不补偿调用 Issue close API。no-Issue 不制造 Issue identity；reference-only、non-default-base 与 source 剩余责任必须按真实 authority 判断。退休 Publication/Finalizer/closing-keyword 自动关闭链只用于其 pinned 历史安装，不能作为当前 lifecycle。ADR-013/024/025 及各 current Interface 拥有具体接口。
- `ARCH-GOV-010`：active-task continuation先消费current adjacent DTO；output丢失时回最近合法原owner。任何status、Git shape、旧摘要、旧确认或retired checkpoint都不能重建semantic pass。确认仅存在于当前对话，新的副作用或authority变化必须重新展示。
- `ARCH-GOV-011`：一个 active Task 可以产生多个独立 Delivery。每个 Delivery 含 D1 都有选定的独立 Planning 与原质量门禁，沿公共 Task/Delivery identity、selection 和转换执行；任何文件存在或旧历史都不能生成当前 semantic pass。`delivered` 唯一交给 Completion，Task 在整体完成前保持 active，不得表达或触发 Issue closure、archive、Finish、Cleanup 或 Reactivate。旧 #435 additive/deferred graph 仅属历史切换阶段；当前只使用一套匹配的公共 graph，不提供 retired lifecycle adapter。
- `ARCH-GOV-012`：当前知识按完整能力或职责单元读取和维护，保留稳定 ID/alias、状态、原 owner、适用来源、晋升依据、条件、例外、顺序、替代范围及必要 R/D/T/Architecture 关系。稳定入口给职责目录和限定发现方法，单元正文拥有完整语义；检索只定位，不建立 authority。原维护方把隔离贡献合入完整当前正文，普通查询无需回放已迁移单元的贡献链。独立主题只写自身完整单元、单元目录内导航和真实受影响的引用；不向根/下级共享 README、system/ownership 汇总、ADR index、共享 metadata 或生成需提交索引登记，不追加无关全局版本或合并历史。只有入口自身身份、scope/status、位置、发现合同或必要跨体系关系实际变化才修改入口。同能力或同一有效关系是真实重叠，由原 owner 比较适用来源、双方 proposal、实际目标和受影响消费者，保留仍有效条件；文本自动合并不替代语义判断。未迁移对象继续指向原完整来源，缺来源、晋升依据、断链、冲突或不完整迁移回原 repair/澄清。达切换条件后新写停止旧共享索引登记；在途 Task 保阶段适用旧读，最终集成命中迁移单元时仍整合到真实当前目标，不恢复旧索引双写。FOUNDATION 的[技术基线选择](../00-foundation/stack-selection.md)固定通用源/version 与项目差异，各自原 owner 在自身边界维护；源接受、项目选择和 CURRENT 实现证据是不同事实。导航决定与替代边界见 [ADR-KNOWLEDGE-NAVIGATION-ISOLATION](../adr/knowledge-navigation-isolation.md)，采用与退出见 [MIGRATION-711](../../../trellis/presets/guru-team/MIGRATION-711.md)。

完整项目 change contract 与 project-check descriptor 见 [`change-contract.md`](./change-contract.md)。
