# ADR-031：完整当前知识单元与两层栈来源

状态：accepted。Owner：原 Architecture Baseline 维护方。适用：#331 的当前知识组织差额；不改变既有Skill public I/O。

## 背景

当前入口的薄继承与任务贡献保留演进证据，但普通能力查询需拼接多轮历史。架构治理还需应用尾部后继才能得到执行顺序。完整性必须先于读取成本；原RDT/Architecture owners、贡献隔离及阶段适用性均须保留。

## 决策

晋升产生按能力/职责组织的完整当前定义。导航只定位，贡献继续记录来源，历史从不可变版本/Git进入。三层RDT保持稳定身份和必要关系；Architecture保留语义分区。替代、删除、拆分、合并保留可追踪关系，不按展示顺序重编号。

通用技术栈由明确版本的公共源拥有正文。项目foundation仅拥有选择、范围、约束、差异及精确来源。源不可得或迁移未完时，原owner说明受影响结论并repair，不虚构完整性。

沿ADR-028保留旧Task的阶段适用来源。新规则只维护新current；旧普通读取在真实依赖结束/合法改选后退出，历史追溯保留。晋升继续遵守ADR-030，完整候选及proposed delta先独立Phase2，实际写入再最终Check/commit/独立Review。

## 取舍与验证

采用现有Markdown/Skill/preset，不建知识服务、自动语义选版、双读解析器或第二owner。初次迁移需要人工逐条核对和导航维护，收益须由同问题、同模型、重复native对照证明。保留未迁移legacy清单及原来源，禁止以代表性迁移冒充全corpus完成。未达到正确性或真实成本判据时不晋升为已验证完成。
