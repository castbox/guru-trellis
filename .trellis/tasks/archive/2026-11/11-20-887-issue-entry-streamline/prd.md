# 缩短 Issue 创建和独立审核流程

## 1. 来源与术语

| 来源 | 角色 | 用途 |
| --- | --- | --- |
| [#887](https://github.com/castbox/guru-trellis/issues/887)「目标与范围」「验收」 | 要求 | 定义交付入口及真实 Agent 对照验收 |
| [#887 候选设计及初审](https://github.com/castbox/guru-trellis/issues/887#issuecomment-7039607153) | 建议与证据 | 确定候选分流及现有耗时证据边界 |
| [#819](https://github.com/castbox/guru-trellis/issues/819)、[#736](https://github.com/castbox/guru-trellis/issues/736) | 关联责任 | 核对正式开工和既有 Task 续接边界 |

独立需求审核判断 Issue 的需求是否充分。独立开工就绪审核另外判断交付单位及前置条件。复审以已有审核为起点，检查它对当前内容和依据是否仍适用。

## 2. 背景与问题

当前只建单从 Sync 经 Discovery、Clarify 和 Readiness 才进入 Create Issue。独立需求审核也先取得 Discovery 上下文。#819 已实现正式开工时按缺口复核，不能据此判定独立审核或复审也已减少调查。#887 记录了一次约七分钟的建单准备样本。独立审核缺少耗时对照。

## 3. 目标与非目标

减少只建单、独立需求审核、独立开工就绪审核和复审的交接、重复调查及不必要重试。保留共享正文规范、已确认的设计、验收和中文技术写作。本 Task 的验收止于 Issue 创建及独立审核入口，并验证确实请求开工时可进入既有开工入口。已有 Task 续接由 #736 承担，#819 的正式开工复核沿用现有合同。

## 4. 真实调用方、场景与流程

| 场景 | 调用与条件 | 结果 |
| --- | --- | --- |
| S1 | Agent 收到只建 Issue 请求，用户已给足资料 | 核对仓库、重复项与相关来源，呈现完整标题、正文、审核评论。确认后创建和回读 |
| S2 | 用户请求审核现有 Issue 的需求 | 读取当前 Issue 和有效讨论，定向补查，返回审核范围、发现和未决项 |
| S3 | 用户明确请求只判断能否开工 | 审核范围、独立交付性和前置依赖，按缺口补查并给出结论 |
| S4 | 用户请求复审，或确认前发生正常过期 | 核对本轮变化，沿用仍适用证据，刷新受影响判断 |
| S5 | 用户确认建单后结果丢失，或请求同时开工 | 找回同一 Issue 和评论。有开工意图时进入原开工入口 |

## 5. 行为要求

- R1（S1）采用当前资料决定补查范围。完整标题、正文、验收及审核评论均达到造单前标准后，才呈现具体写入并取得确认。Create Issue 回读原 Issue 和审核评论。
- R2（S2、S4）独立需求审核先读实时 Issue 和有效讨论。只补查影响需求、范围或验收的证据。复审对照正文、讨论和相关来源变化并保留适用覆盖。只读请求返回结论。
- R3（S3、S4）独立就绪审核保留独立可交付性和依赖判断。先复用适用覆盖，有实际缺口才调用对应步骤。只读请求返回结论。
- R4（S4）正文、范围或实质依据变化时重审受影响部分。只有重复项查询过期时，刷新查询并核对待写内容，保留仍适用的正文审核。调用错误给出原步骤、具体错误和重试入口。
- R5（S5）获得确认的建单保持原写入与同对象恢复合同。只有用户同时要求开工时才进入原开工入口，并由该入口判断其前置证据。

## 6. 约束与依赖

Workflow 拥有跨步骤路由，Skill 拥有语义判断和写入条件。脚本执行读取、写入和客观校验。计划明确当前调用方兼容及迁移。目标仓库或必要来源不可读时，相应结论或写入依其原合同停止。

## 7. 可观察验收与验证方式

- AC01（R1–R3）在相同材料、相同 Agent 宿主条件下对照基线与候选的正常入口，覆盖资料齐备的只建单、独立需求审核及独立就绪审核。记录从请求到首个可审阅结果的耗时、实际阶段调用和重试。用户确认等待单列。候选提供完整正文或有据的结论，并可举证减少交接或重复调查。
- AC02（R2–R4）用证据仍适用的复审对照，记录耗时、调用和重试。以实际证据缺口、实质变化及仅重复项过期场景验证补查、局部重审与内容审核复用。
- AC03（R1、R3、R5）用受控材料验证只读入口无写入、获确认的建单回读两对象、输出丢失恢复原对象及显式开工调用既有入口。验证区分真实 Agent 行为与可机械验证的执行结果。
