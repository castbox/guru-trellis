# D1 Issue 创建与独立审核

## 1. 整体来源与术语

整体范围见 [Task PRD](../../prd.md) 第 3–7 节。D1 的公共 scope_ref 选用 AC01、AC02、AC03。Direct Source [#887](https://github.com/castbox/guru-trellis/issues/887) 的目标、范围和验收是要求，候选设计和初审用于选择方案。

## 2. 整体与本批目标、非目标

在一个可交付切片内完成创建、独立需求审核、独立就绪审核及复审的分流。减少阶段交接、参数组装和重复调查。保留共享正文义务、写入确认、同对象回复及 #819 开工入口。#736 的既有 Task 续接和版本发布不属于本批。

## 3. 本批起点、前序结果、依赖与剩余责任

首次 Delivery，无前序。开发起点为 `61da60132bd0f6b64ab8626ac3158093481cd21e`。依赖现有 GitHub 读取、写入和回读合同、正文规范、工作流与安装投影。所有受支持分支和真实对照验证完成后，本批可支持整体 Completion。

## 4. 本批调用方、场景与流程

- D1-S1。只建单且材料充分时，Agent 确认目标与重复项，审核完整标题、正文和评论，提供具体写入预览。用户确认后执行并读回。资料有缺口时，原 owner 定向补查。
- D1-S2。独立需求审核先读当前 Issue 和有效讨论。仓库证据影响需求结论时才查指定来源。输出实际覆盖、发现和未决项。
- D1-S3。独立就绪审核先判断本次已有证据，判断范围、独立可交付性和前置依赖。定向补足实际缺口后给出开工结论。
- D1-S4。复审先比对正文、讨论及相关来源。仅重新审核受影响部分。写入前只遇到重复项过期时刷新查重，保留仍适用的正文审核。
- D1-S5。获确认的写入中断时，执行器恢复同一 Issue 和评论。用户同时请求开工时，正式 Issue 进入既有 Sync 和开工复核。

## 5. 完整行为、条件与约束

保留整体 R1–R5。只读结果结束于当前请求。证据影响和路由由各原语义 owner 决定。机械校验只绑定准确内容和本次操作。调用错误按原步骤说明缺失、冲突或合法重试入口。继续兼容已公开的完整链和在途恢复输入。

## 6. 本批验收、验证方式与未决项

用一个对照场景集覆盖四个真实 Agent 入口，可见耗时、步骤、重试和不含确认等待的结果。用有明确缺口或正常变化的材料验证 D1-S2 至 D1-S4。通过原 Create Issue 的实际写入及回读边界验证 D1-S1 与 D1-S5。计划须指明每项使用的验证环境和证据边界。入口与兼容实现交 Architecture 和 Author 方案阶段细化。
