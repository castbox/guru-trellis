# 跨 Issue 协调者的整体完成与主动解阻

## 1. 来源与术语

Direct Source：https://github.com/castbox/guru-trellis/issues/731。已完整读取当前正文及评论（当前无评论）。行为要求、修改范围及九项验收为要求；现场聊天是历史线索，不能作为当前候选的通过证据。来源中的共享方法优先、原 owner、调度与安装边界为约定设计约束。#666 是关联背景，不是新硬前置。

当前实现来源：canonical issue-orchestration.md、两个 package 的 SKILL.md 与 DAG/chain contract。Codex 分发约束来自 docs/requirements/current/codex-skill-distribution.md 及对应 design。

终点是当前用户约定的阶段；步骤失败、Check blocked、节点等待与整个编排终局阻塞不同。用户选择较早终点时不得扩大。

## 2. 背景与问题

现有共享方法已有观察、恢复和完成证明，但可能退化为观察子会话、发送通用确认。无建议时主动调查、等待失效后的再判断和持续追踪未充分展开。现有 forward cases 主要验证下一步，不能证明真实 Agent 能推进到终点。历史中也有明确用户限制导致的合法暂停，不能全部判为缺陷。

## 3. 目标与非目标

在既有目标、范围和当前对话授权内，对全部选定 Issue 的约定终点持续负责。具体实现和正式 gate 保持原 owner。

不接管、发消息或改变原业务会话，不修业务问题，不操作生产或发布版本；不重写单 Issue 生命周期。不新增调度脚本、机械决策器、持久协调台账、授权记录或固定审批链。不修改上游、全局包或 node_modules。不承担完整多平台 Release/Upgrade 矩阵。

## 4. 真实调用方、场景与流程

| ID | 调用方、前提与触发 | 处理和可观察结果 |
| --- | --- | --- |
| S1 | DAG/Sequence 协调 Agent；子会话顺利推进或阶段结束 | 轻量观察、判断剩余义务并衔接原 owner；终点达成后核证结束 |
| S2 | 子会话 blocked、失败、无建议或终点前停下，仍有调查方向 | 调研事实、商讨、协调或适用审核，选择有依据动作并追踪结果到终点 |
| S3 | 阻塞、推荐或完成声明证据不足 | 质疑并核证，要求原 owner 修正与验证，不代填正式通过 |
| S4 | 普通输入/路径/前置错误或旧事务不可恢复 | 保留旧失败和同 Issue/Task/Delivery，区分原操作恢复与合法后续执行 |
| S5 | 有明确外部责任方、对象和复查条件的等待 | 核真实外部条件与等待有效性；条件变化、结束、超时、无人承接或失效后再处置 |
| S6 | 外部条件、授权、真实选择或必需工具/gate 无支持路径 | 先核当前入口、原 owner 修正/等价路径和范围内修复；确实无工作可推进后最小请求并安全收口 |

DAG 只暂停真正受影响的工作，依原 failure policy 继续独立节点。Sequence 当前项完整完成后才推进下一项。不能跳节点、削弱依赖或降低验收。

## 5. 行为要求

- R1：掌握目标、依赖、剩余义务及终点；发送指令、观察一轮、子会话结束或单 Delivery 合并都不是整体完成。
- R2：按真实需要提醒遗漏、调研仓库/外部事实、与原 Agent 商讨、协调资源、质疑不足声明，并按原合同组织必要独立 review。顺利路径不固定访谈、质问或审核。
- R3：没有现成建议也要从目标和已知事实识别遗漏方向；询问一次或机械转发不算解阻。每次行动解决真实缺口，根据结果更新判断。不无依据同配置重试、无限实验、穷举理论方案或反复审计。
- R4：旧事务无法恢复不单独证明 Issue 无法继续；核修正输入、路径、前置或范围内实现后原公开入口的合法后续执行。未知副作用先恢复原操作，不重复执行。用户明确停止条件始终有效。
- R5：外部等待必须有责任方、对象和复查条件；核实际外部条件及原等待有效性，不能只比较子会话文字。通知去重不得永久保留失效等待，心跳静默仅控制通知频率。
- R6：终局阻塞前完成有依据的解阻判断，并确认不存在仍可推进的范围内工作。报告目标缺口、已核可行路径与不能继续原因、责任方最小条件或真实选择、恢复条件及受影响节点。无需穷举方案或新增证明文件。不能擅自修框架或以直接证据替必需 producer。
- R7：保留两技能显式调用、调度差异、身份/资源归属、单一集成 owner、语义 gate、确认边界和公开出口。只用 Markdown/AI 判断；原安装 owner 同步 dogfood/installed。
- R8：真实 Agent 从正常公开入口运行隔离诚实场景。只给目标、事实和边界，不预填正确解法、下一路由或预期通过；工具只供事实/子会话状态及实际所选动作结果。观察多轮发现障碍→调研/商讨/审核→执行处置→接收结果→再判断。
- R9：实施前刷新采用现场的原入口、provider/版本、终点、约束、子会话输出、首个失当处置和可推进路径；提供可移植去敏说明，聊天链接不作唯一来源。不可访问时明确缺项，通过当前正常入口补调查，不编造历史。确证缺陷保留首处置和修复后对照；不复现时诚实说明覆盖/缺口。

## 6. 约束与依赖

优先收敛共享方法，同步两 canonical Skill、DAG/chain contract、心跳及必要示例/导航/投影。公共 API 无预定变化，必要变更回原迁移合同。无新增数据字段或存储，因此无数据迁移。

只处理正常诚实流程，不扩展攻击、篡改、竞态压力或 crash 加固。不得泄露秘密、业务敏感原始记录或持久化授权过程。保留原安全停妥、原生工具回读及原 run 恢复。
