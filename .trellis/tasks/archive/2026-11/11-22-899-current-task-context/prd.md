# 当前 Task 续接通过一次只读调用解析身份与位置

## 1. 来源与术语

| 来源 | 角色 | 用途 |
| --- | --- | --- |
| [#899](https://github.com/castbox/guru-trellis/issues/899) 的问题与目标、行为要求和验收 | 直接需求 | 定义整体交付范围 |
| [#899 审核评论](https://github.com/castbox/guru-trellis/issues/899#issuecomment-7078983158) | 审核证据 | 核对与 #657、#814、#822 的交付边界 |
| [#736](https://github.com/castbox/guru-trellis/issues/736) 第 2 项与 AC3 | 上游来源 | 解释一次身份解析的目标 |
| [Guru Workflow](../../workflow.md#bound-formal-task--delivery-continuation) 的绑定 Task 续接 | 当前行为 | 定位实际调用方和后继入口 |

Task generation 区分同一 Task 的不同生命周期。当前 Delivery 是当前会话在该 Task 下选择的交付对象。checkout 指已通过分支绑定和 Git 注册关系校验的工作目录。

## 2. 背景与问题

固定起点为 `origin/main@f06eddb6ccf97ddd2d1a41c117692f5957cb2dc7`。标准续接先解析 TaskId、generation、分支绑定和 checkout，再执行当前 Delivery 查询。调用方需要分别取得并组合这些事实。#814 优化了原生 context 的多工作区查询开销。一次公开解析仍需接入标准续接。

## 3. 目标与非目标

标准续接调用方通过一次公开只读调用取得当前义务所需的最小定位信息。整体交付包括入口接线、受影响的公开合同与平台投影，以及对应验收。创建、修复、切换、迁移和终态处理仍归各原负责人。

## 4. 真实调用方、场景与流程

| 场景 | 触发条件 | 可观察结果 |
| --- | --- | --- |
| S1 绑定 Task | 标准续接入口收到当前会话的继续请求 | 有可续接 Delivery 时定位该 Delivery 及下一步。没有当前 Delivery 时继续 Task 原有义务。当前选择已进入终态时交原终态入口。 |
| S2 同一会话再次续接 | 上次结果仍可用，或相关关系正常变化 | 复用仍适用的事实。关系变化时重新验证受影响部分。 |
| S3 无绑定或关系异常 | 标准入口无当前绑定，或发现普通过期、冲突、歧义或旧合同记录 | 区分无当前 Task、允许的显式只读查询、需要原绑定恢复以及具体诊断。 |

## 5. 行为要求

- R1 对受支持的当前 Task，返回 TaskId、generation、已验证 checkout，以及区分可续接、无当前 Delivery 和终态所需的最小事实。仅在需要时返回 Delivery 的最小定位信息。
- R2 同一会话可复用仍适用的结果。TaskId、generation、分支与 checkout 的对应关系、会话绑定、当前 Delivery 选择或相关来源变化时，刷新受影响的事实。
- R3 无当前绑定且请求未指向已知 Task 时，明确返回无当前 Task，由原入口处理后续选择。已知 Task 且原合同允许显式只读查询时沿原查询承接。实际续接要求绑定而绑定缺失时，指向原绑定恢复入口。
- R4 普通过期、冲突、歧义及旧合同记录保留具体诊断、原负责人和解除条件，并区分可直接查询、需要原步骤恢复和超出支持范围。
- R5 查询仅用于定位当前义务。Task、绑定和 Git 资源保持原状态。创建、修复、切换和迁移通过原入口执行。原恢复事务保留已经合法写入的结果。

## 6. 约束与依赖

复用现有 Task、session、checkout 和 Delivery 查询及无写入续接能力。同步说明受影响入口的真实前置、最小调用、结果和诊断的消费方式，以及兼容边界。公开调用形态与实现落点由 Delivery 规划确定。

## 7. 可观察验收与验证方式

- AC1 对应 S1、S2 和 R1、R2、R5。从同一个标准续接入口观察有当前 Delivery、无当前 Delivery 与终态的承接。确认调用方只执行一次公开解析。同一会话再次调用时验证结果复用，再用正常关系变化核对刷新。比较查询前后的 Task、绑定和 Git 资源状态。
- AC2 对应 S3 和 R3–R5。从该入口核对普通无当前 Task、已知 Task 缺少必要绑定、普通过期或冲突以及受支持的旧合同记录。观察显式只读查询与绑定恢复的区别，并核对诊断和原负责人的承接。采用仍适用的恢复证据，并补验新接口影响的恢复路径。
- 定向验证变更的公开调用及受影响的声明平台投影。

## 8. 实际未决项

整体范围没有待确认的需求选择。命令、返回合同和同一会话内结果复用的实现由 Delivery 规划细化。
