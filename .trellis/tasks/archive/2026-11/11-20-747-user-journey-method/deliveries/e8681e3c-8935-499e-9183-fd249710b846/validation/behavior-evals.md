# D2 工程验证

## V2–V4 原生方法观察

使用现有 #735 采集入口，在隔离目录通过 Codex CLI 的 `exec --ephemeral --json` 运行。独立评价者在运行前冻结预期。运行后，评价者分别核对实际输入、读取顺序、工具返回和原生输出。

| 观察 | 实际结果 |
| --- | --- |
| V2 · 最小完整旅程 | 首轮区分了各层证据，但漏读新增验证方法，也未明确旅程优先。保留首轮记录。复跑使用相同事实，只补上验证方法的小节位置。Agent 读取方法后，计划先走真实长按、Paste、选片、焦点恢复、保存和重开，再复用适用的 ASCII/Unicode 回归证据。它限定了直接方法、setter 和同实例替身的覆盖范围。支持 JQ-AC3、AC4。 |
| V3 · 媒体与草稿恢复 | Agent 先从已接受行为提出核对问题，再打开候选。它指出单个 H264/AAC 暖缓存样本的结论不能覆盖 HEVC/PCM 发货能力。它要求在对应构建中核对两种已承诺组合，并从真实重启、新对象恢复、地址续期追踪到可播放首帧。补验限于已接受的组合及实际路径。支持 JQ-AC4 至 AC6。 |
| V4 · 简单函数 | Agent 计划用现有运行器直接验证 `trimName` 的返回值，覆盖首尾空白、内部字符、大小写和空字符串。它选择的层级足以观察约定结果。支持 JQ-AC3、AC6。 |

三组原生记录共同支持 JQ-AC8 的去敏方法观察。实际执行有读取边界偏差。Agent 在完成本地规范加载前读取了事实，也读取了目录外通用 Go-Guru 技能正文。原始返回未发现预置答案、历史结果或其他观察素材。V4 未读完 Phase 2 指向的工作流合同小节。V3 在打开候选前提出核对问题的顺序可直接从原始记录验证。保留原始记录及首轮偏差，方法观察的结论限于此组素材。设备测试、产品运行与正式 Check 均未在这些素材中执行。
