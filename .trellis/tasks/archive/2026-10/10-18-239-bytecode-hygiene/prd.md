# #239 字节码过滤与无落盘语法检查整体需求

## 1. 来源与术语

Direct Source：[Issue #239](https://github.com/castbox/guru-trellis/issues/239)，完整目标、R1–R3、验收标准与非目标为本 Task 要求。当前请求要求以 main 为基线完成实现及交付；Issue 末尾“本次仅修订”描述的是先前 Issue 修订轮次。#430 / PR #431 是已交付历史能力，保留其回归，不重复实现。

产品资产指 canonical Guru 文件、预设/运行时安装副本和所选平台的 Guru 管理 `guru-*` 文件。dogfood 指本仓库实际运行的安装副本。字节码指路径分量为 `__pycache__` 的内容及后缀 `.pyc`、`.pyo` 文件。

## 2. 背景与问题

main `ed59e851b6c1257bac6316a9571274427e383c93` 中 `_tree_files()` 仅过滤 `__pycache__`。在真实安装副本的临时复制中，基线完整 verify 通过；普通编译工具生成相邻 `.pyc` 后，原 Python 未变却报 file set drift。常规规范仍要求 `py_compile`，即使 `-B` 和禁写环境也会生成缓存。安装器、`collect_files()`、`tree_sha256()` 已正确排除三类字节码。

## 3. 目标与非目标

完整修复两个剩余缺口，核查直接相关工具，通过现有机制同步实际受影响安装副本，完成定向回归和交付。整体 Completion 必须逐项核对下列验收，不能用 PR 合并替代。

不扫描、摘要、迁移或改动业务仓自有 Python、测试、产物、缓存、`.gitignore`、入口、快照与发布身份。虚拟环境、第三方和私有运行缓存不属于产品。不得清理源码现有忽略缓存。不扩展到全部入口快照化、统一投影/摘要引擎、缓存基线、审批台账或持久证明报告；不改变公共 API、身份编码或工具合法范围。无恶意输入、锁、压力或崩溃加固。无业务仓升级、软件发布、生产操作、Trellis 上游或 npm 修改。无历史 Trellis、多 workflow、动态 spec 或完整发布矩阵责任。

## 4. 真实调用方、场景与流程

| 场景 | 调用方、前置与触发 | 行为及观察 |
| --- | --- | --- |
| S1 | dogfood checker 读取一致的真实 Guru 安装副本 | 完整 verify 通过；普通编译新增/改变三类字节码后仍通过，缓存保持原样 |
| S2 | 同一 checker 读取缺失或变化的真实产品文件 | 继续按原规则失败，不因过滤放过产品漂移 |
| S3 | Agent 按常规规范检查合法或语法错误的 Guru Python | 只编译不执行；合法成功，错误失败并指出文件与原因；产品与既有缓存不变且无新缓存 |
| S4 | installer/runtime/资格验证及产品临时副本创建调用方 | 各自在原资产范围忽略三类字节码；真实产品差异仍可观察 |
| S5 | 维护者通过现有 preset/managed spec 同步与重复应用 | canonical/dogfood/平台一致；正常重复应用无新 sidecar 或非预期 tracked 变化 |

先核对当前状态，再修复已复现的原职责缺口，运行定向验证，最后同步和重复应用。不得通过清理缓存制造通过。

## 5. 行为要求

- **R1 / S1、S2、S4**：Guru 产品文件清单、内容摘要、一致性与隔离产品副本排除 `__pycache__` 分量及 `.pyc/.pyo` 文件。只改变缓存数量、路径、内容或大小时产品判断保持不变。保留真实产品缺失/变化检测。保留既有正确实现；其它路径仅在正常操作复现同类遗漏后修改。不统一工具范围、排序、公开/私有划分、哈希算法或格式。不建立缓存数量、大小、mtime、hash 等基线。
- **R2 / S3**：常规文档的落盘 `py_compile/compileall` 替换为内存 `compile(source_bytes, filename, "exec", dont_inherit=True)` 或等效检查。覆盖原命令的 Guru 文件范围；不执行模块、不生成缓存、不清理缓存；语法错误必须失败且指出文件和原因。仅字节码专项回归可在隔离临时目录使用编译工具。
- **R3 / S5**：从 canonical 修改，经现有 preset、managed spec、平台机制同步 dogfood 与受影响安装副本。若适配临时副本，只改 Guru 产品资产；保留执行前后检查并区分产品变化与执行缓存。无需所有入口改快照或新增公共协议。

## 6. 约束与依赖

遵守 AGENTS 的正常协作、脚本确定性和 canonical 优先边界。现有 CLI、哈希编码、平台选择与发布候选 provenance 保持；无新持久化字段，因此无数据迁移。依赖当前匹配 Guru preset 和 managed Python；环境失败如实记录，不能算通过。相关源文件过滤可直接修正，不为未来预留框架。完整安装矩阵由专门 Issue 承担。

## 7. 可观察验收与验证方式

- **AC1 / R1、S1–S2**：真实 Guru 安装副本的隔离复制上完整 verify 基线通过；新增并改变三类普通字节码仍通过，检查不改缓存；真实产品修改或删除失败。
- **AC2 / R1、S4**：定向调用安装器、runtime、资格摘要和本轮影响的复制入口，分别验证原范围内排除字节码且保留真实内容差异；已有正确工具只做必要回归。
- **AC3 / R2、S3**：实际文档命令覆盖原范围；合法源码成功，语法错误失败，输出含文件/原因；前后产品与已有字节码不变且无新增缓存。
- **AC4 / R3、S5**：相关包/集成测试、所有权、canonical/installed 与平台 drift 检查通过；preset 重复应用无新 `.new/.bak` 或非预期 tracked 变化；保留 #430 回归。
- **AC5 / R3**：仅新增安装资产或布局变化时执行最多一个当前版本代表性 clean 临时安装；无布局变化则不为形式验收增加安装。最终报告明确完整多平台、历史升级及发布候选矩阵未执行。
