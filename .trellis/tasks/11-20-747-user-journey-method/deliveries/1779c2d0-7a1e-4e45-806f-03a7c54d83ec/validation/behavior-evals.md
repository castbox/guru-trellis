# D1 工程验证

## V1 原生方法观察

使用 Codex CLI 0.167.0 的 `exec --ephemeral --json`。两条观察使用同一套冻结的中性来源、组件事实及交接候选。被测进程使用候选 Guru provider。独立评价者在运行前冻结判据，运行后核对完整输出和读取记录。

Clarify/Author 复跑从实际编辑入口推导等待上传期间改选、局部确认后离开、草稿恢复和最终发布。它保留 System Back 的产品未决项，指出最后一个资源句柄提前释放会删除片段，要求原技术负责人修订接管顺序和失败后的归属。独立 Approval 观察先提出从来源推导的问题，再打开另一方提供的候选。它检出同一交接空档，要求调整设计和正常流程验证。这些观察支持 JQ-AC1、AC2、D1 适用的 AC6 和 AC8。

Clarify/Author 首轮读取本机记忆文件。原始记录保留，独立评价未采用该轮。关闭记忆加载后复跑，轨迹曾列举外部工具目录的名称，未读取其中的文件正文。独立评价核对了实际输入、来源和候选的读取顺序，未发现答案从外部进入。原执行和复跑的输入、工具记录、输出及结果保留在工作区外。观察范围为本例中的方法执行。真实业务应用及正式 fixture 生命周期门禁未执行。
