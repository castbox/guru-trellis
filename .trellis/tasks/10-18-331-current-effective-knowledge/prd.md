**当前有效知识**是经确认且适用于本次问题、Task、阶段与候选内容的正文及必要关联。它既不等同最新仓库版本，也不只指已实现能力。已接受目标按目标使用，不冒充当前实现。来源、版本和适用性由原维护 Skill 判断。

**必要关联知识**包括理解或修改对象所需的条件、例外、依赖、设计、测试与架构约束。链接不无限展开；Agent 判断与当前问题的关系。**稳定标识**拥有知识身份，不与章节位置、展示顺序绑定。RDT 指 Requirement、Design、Test Plan 及必要追踪。

## 2. 背景与问题

RDT 与 Architecture 已有生命周期管理。RDT 当前入口 `.109` 继承 `.108` 并链接任务贡献。Architecture `.100` 保留旧条目，并以 #600 / ADR-030 等后继说明替代范围。查询能力、行为、接口或职责时，Agent 仍须跨版本和任务拼接，判断哪些条件继续有效。

这种结构保留来源，但当前正文、历史与增量交织。单次检索命中不能直接建立当前答案；局部修订也要跨贡献查找影响。遗漏率和节省量尚未测量。实施前必须固定对照基线，不能凭更短入口宣称改善。

## 3. 目标与非目标

整体目标是让 Agent 按当前问题找到完整适用知识，并在需求或实现变化时一致修订受影响知识，减少无关历史回放和维护。

整体范围同时包括 RDT、通用技术栈基线和项目内架构选择/约束/决策投影，以及本仓库实际采用、兼容迁移、日常维护入口、真实 Agent 对照和受管安装更新。一个局部导航或单一样例不构成 Task Completion；允许分批 Delivery，但每批须明确剩余责任。

非目标：不指定 Obsidian、图数据库、向量检索、标签、双链、外部服务或固定目录；不新增审批链或遥测平台；不以摘要、省略追踪、删除有效约束换取低成本；不重写历史快照或全部业务文档；不自动迁移业务生产仓；不重建外部通用基线服务；不重写从零建立 RDT 的既有方法。不增加恶意伪造、对抗绕过、额外锁、压力竞态或 crash-consistency 加固。完整多平台 Release 矩阵由专门门禁承担。

## 5. 行为要求

### R331-01 按问题读取完整知识

支持 S331-01/02/08/09。入口须覆盖能力、行为、接口、架构职责和稳定引用。当前有效要求、已接受目标、未确认内容、历史决策和被替代内容可区分。存在替代时，原 owner 判断有效定义、继承条件及替代范围。历史与来源可追溯，但不成为普通当前查询的强制拼接链。

正文保留必要条件、否定、例外、顺序和跨文档约束。不以不完整摘要代替权威正文，不按日期、编号或搜索排名自动决定有效性。缺来源或有未解决冲突时，限定结论并走原维护路径。

### R331-02 局部且一致的知识修订

支持 S331-03/04/05。从本次变更找到受影响的需求、设计、测试与架构知识，并说明无需修改对象的依据。稳定标识与关系可跨新增、修改、替换、删除、拆分、合并保持。展示顺序改变不迫使无关重编号。

贡献晋升后，后续 Agent 能直接取得该能力当前定义。贡献保留变更来源与历史责任，不能成为长期拼接答案的唯一方式。新结构必须进入原 Planning、实现、Check、Review 和晋升流程，不能只增加入口而继续维护旧结构。

### R331-03 两体系与两层架构来源

RDT 保留 `requirement/behavior -> design responsibility/contract -> test strategy/scenario/case` 的必要追踪。局部改动不得遗漏关联层或产生含义冲突。

通用技术栈基线由原维护方拥有正文；项目 owner 只维护项目选择、范围、约束和差异。修改项目投影不授权修改共享正文或自动升级别的项目；项目私有内容不得混入公共基线。

外部基线通过明确位置和版本引用。Planning 查明实际来源、取得方式和维护边界；必要来源无法取得时不宣称对应验证通过，可用来源明确的去敏副本或临时样本验证合同，但不能冒充外部采用事实。

Architecture 的 FOUNDATION、CURRENT、TARGET、GAP、PLAN、ADR、EVIDENCE 继续分责；基线与 ADR 不混同。RDT 和 Architecture 各保留唯一维护 Skill，跨体系只引用必要约束，不复制成第二权威。

### R331-04 正文、入口、历史与 AI 职责

明确组织单位、正文唯一维护方、查询入口、关系和历史边界。导航、索引、投影或摘要有具体用途和维护方法。修订后入口仍能到达完整适用正文，失效定义不继续作为当前答案。修复沿原维护路径，不建第二事实维护流程。

AI 判断来源、语义、关联、替代、修订充分性和路线；脚本仅执行明确读取、提取、生成、写入和机械校验。保留稳定标识、隔离贡献、正常并行、受控晋升和阶段适用性。写作/审核能力只能在 Guru 生命周期下复用，不形成独立生效结果。

### R331-05 兼容迁移与分发

迁移合同覆盖当前知识、历史、稳定引用和未完成 Task 的适用版本。切换前明确影响文件、版本、切换条件和失败恢复。迁移未完成则原权威保持可读，缺口明确，不报告切换成功。不能静默丢失有效行为、约束、关系或来源；无法判断的历史冲突回原 owner，不自动合并为确认知识。

不重写历史，不强制切换在途 Task。保留旧读取路径时，说明真实 consumer、范围、owner、退出/删除条件，禁止无限期双写。破坏性 public I/O、schema 或路径变化必须明确版本和迁移边界。

改动落到 canonical workflow、Skills、spec/preset，同步适用 dogfood 与完整安装副本。已有项目按匹配版本声明更新路径采用；保留用户修改，处理 `.new` / `.bak`，不能把 source 改动当成现有安装已经更新。

### R331-06 对照和收益证据

在实施前固定样本、每样本必答事实、必要约束、关联修订范围、执行次数、汇总方式和成本判据。覆盖 S331-01..09；允许同样本覆盖多项，无需九个工程。

新旧保持问题、来源语义和预期答案一致。结构、入口和读取指令可不同；核对没有靠删要求降低难度。真实 Agent 使用相同模型版本、权限和起点，分别从正常入口开始，不预载另一方案答案或轨迹。文档正文、自动注入和工具读取指令均计入成本，不能把全文搬到注入后声称节省。改变样本或环境须说明原因并同口径重跑双方，不能用一次偶然成功证明稳定收益。

报告正确性、读取成本、维护成本、真实 Agent 行为、安装更新五类结果。正文、导航、重复读取、无关历史和生成视图维护成本分别说明。历史拼接查询须有实质读取改善；修订样本须减少历史拼接或无关维护；兼容样本只要求正确。正确性失败不能用成本下降抵消。列出全部样本结果，保留首次失败和修复；无需完整对话或长期遥测。
