# D2 升级候选版本同步需求

## 1. 整体来源与术语

本批选择整体 PRD 的 AC02a。#924 与仓库私有发布合同要求使用已交付的完整干净源码执行 `source_locked`。现有升级入口同时消费候选版本常量和升级结果 schema。

## 2. 整体与本批目标、非目标

使升级入口和输出合同接受当前 .12 发行候选。真实目标安装采用属于后继 AC02。正式发布由准备收尾后的候选流程执行。

## 3. 本批起点、前序结果、依赖与剩余责任

PR #925 合并了扩展版本和文档。真实只读工具预览在校验正式源提交时被既有 `TARGET_GURU=0.7.0-guru.11` 拒绝。上一版发布同步了该常量及对应现有输出 schema，见 Git 提交 `7d1b742f7`。本批修正后由后继 Delivery 运行原工具采用。

## 4. 本批调用方、场景与流程

维护者从当前 .12 源码验证预览。现有工具 owner 应接受匹配的真正候选，继续现有目标检查。独立交付后，后继使用此次实际交付的源码执行同一入口。

## 5. 完整行为、条件与约束

同步现有 canonical 升级 owner、输出 schema 及直接消费者的目标版本。按现有受管流程生成临时安装投影验证。已发布前驱合同继续按其匹配源码恢复。保留 CLI/source lock 和其他版本、来源、权限、工具及 Task 保留约束。来源设计处置见 design 第3节。

## 6. 本批验收、验证方式与未决项

AC02a 由代码、schema、源码投影验证和真实预览证明。用干净的 .12 候选源码及实际匹配 Fork 执行只读 `source_locked` preview，观察它越过原候选版本拒绝并返回当前目标的计划材料。失败时留在本批纠正。无待定需求。

## 7. Canonical 引用与本轮差额

私有发布合同 Stage 1 与 ARCH-INT-014、015 规定源码交付与实际采用的分工。现有升级合同保留原职责，变更限于版本绑定的值。
