## 5. 完整行为、条件与约束



### JQ-R1 正常用户旅程推导

Clarify 在原澄清方法中从当前来源及真实入口推导连续操作：起点、阶段、允许动作、等待期间正常再次操作、成功/失败/放弃后可见结果。仅展开实际适用的部分；无交互任务使用真实调用方。既有行为是调查事实，不能自动决定未明确的产品选择；真正歧义仍在原入口确认。新场景按原资格规则进入，不能从经验构造范围。

### JQ-R2 阶段语义与交接不变量

Author 在已有 PRD/design 位置区分局部确认、后台任务完成、可靠保留、最终提交等本任务实际存在的阶段。对当前涉及的状态或资源交接，说明必须保持的业务条件、先后动作、实际 writer/reader 和失败后归属。Architecture/Approval 依据自身职责检查该条件能否成立，不把技术实现细节转成产品问题。不增加通用锁、并发压力或异常 crash 协议。

### JQ-R3 最小完整旅程优先

存在可运行入口且具备相关依赖时，Author 的 implement 验证计划和实施 owner 优先安排一条最小完整正常旅程，再扩展重复参数。高风险下层行为可以先做定向模块验证；不固定 test-first/implementation-first，不普遍要求设备或全链 E2E。依赖缺失时推进独立工作并记录其真实影响；一条旅程通过不替代必要验收和受影响回归。

### JQ-R4 验证入口、替身和样本的有效性

检查目标行为是否真实经过其入口：菜单经手势唤起、媒体返回后观察焦点、确认从真实页面交接等。直接方法测试在声明层级保持有效，不提升成用户交互证明。比较替身与真实适配器的必要语义：反序列化后对象身份、异步完成、持久化恢复、地址更新、缓存和解码就绪。只验证当前需要的差异，不搭建通用平台。

代表性输入按真实接受范围及目标构建能力选择；容器名不等同于编码组合。支持媒体或其他原生能力的任务，应核对实际交付依赖与样本，不能从 host 构建或单一样本推断全范围。运行工具执行事实，AI 判断充分性。

### JQ-R5 原审核 owner 的独立推导

在各 owner 原有隔离和读取顺序内，先根据来源或其职责 authority 形成关键行为/关系问题，再对照候选设计、实现、测试和实施总结。不向独立检查者预置缺陷答案或通过叙述；不新增 reviewer、轮数或第二架构评估。相同且适用的证据继续复用。

### JQ-R6 必要最小结果

场景、阶段、不变量和验证顺序写回已有 PRD/design/implement 的所属正文。当前结论只说明已覆盖、受改动影响需补验、失败和未执行的必要范围；不复制原日志或建立新账本。历史观察保持原义。

## 6. 本批验收、验证方式与未决项



- JQ-AC1：正常富媒体编辑例子能展开上传中再次编辑、局部确认后退出、恢复与最终保存；区分已有要求、待确认选择和实现细节。
- JQ-AC2：交接例子能识别先删唯一来源引用、后转移到表单的设计缺口，并要求原 owner 修订；不要求用户指定事务代码。
- JQ-AC3：实施例子在入口可运行后先验证真实正常旅程，之后补实际参数缺口；简单函数/API-only 任务不被扩成设备 UI 验收。
- JQ-AC4：测试审查区分直接 paste 方法与长按菜单、内存同实例与真实反序列化、地址存在与实际解码可用；正确限定局部证据，不要求每条测试全链。
- JQ-AC5：代表性媒体例子能发现只有 H264/AAC MOV 样本不能支持 HEVC/PCM 范围结论；不把未知能力自动承诺为支持，也不任意削减已确认范围。
- JQ-AC6：独立检查从原 authority 推导缺口，无答案提示；已有适用覆盖、正式 owner 读取顺序与资格边界不变。
- JQ-AC7：canonical、dogfood 和实际受影响安装投影一致，定向分发/reapply/drift 及必要 package 测试通过。机械检查只证明分发和结构。
- JQ-AC8：使用受支持的实际 Agent 执行入口，对去敏任务材料观察上述行为，记录实际输出和缺口。历史已知 Opening 案例只作回放辅助，不把预写转录、关键词或答案泄漏当语义通过。

没有待用户决定的产品选择；原生Agent执行、分发和依赖装配失败归实际验证边界，不以文字扫描替代。
