## Selected legacy maintenance (#566)

Use the original `scripts/invoke.sh` for terminal history/retirement and
`scripts/legacy-maintenance.sh` only for intermediate inspection. Load from the complete matching source; these
profiles do not accept current ready, Closure or TaskLifecycle input. Read exact
Task/generation, old source inventory and control contents first.
`legacy_control_inspection` is read-only. Before retirement, AI reviews exact
attribution and external PR/push/merge obligations, preserving unknown facts and
external obligations in the original maintenance note. `legacy_control_retirement`
uses only the fixed original maintenance checkpoint and preserved raw source or
readable archive, never the removed active tree. Confirm concrete writes in the
current dialogue when needed; no authorization is serialized. Reject unknown
historical control paths until their original inventory has an exact supported
profile. Preserve terminal Finish, completedAt, sealed resource ledger and all
other Task/generation state. Output legacy_controls_retired only to the selected
maintenance owner; it never means current Finish or Completion.

Only Publish and Merge own `legacy_history_verification`: AI reads the
old source and establishes historical attribution before invoking this read-only
fact validator. Real PR/head/target are reread; Merge requires actual merged SHA
and target ancestry. These facts are only projection evidence, never a gate pass.
Unverified or unavailable history remains raw with its concrete obligation; no
push, merge, Issue mutation, new Delivery or current pass is performed.

## Manual archive source (#577)

For manual archive resume, task_ref retains original active-path attribution.
The optional source_task_ref names the exact physical archive used by this
owner's inspection and freeze; omission retains the existing profile meaning.
Retirement checks the same frozen source and exact controls. This field never
authorizes a different Task or generation. AI must return unfinished Closure,
Finish or Finalizer work to its original transaction before maintenance writes;
terminal Finish results and resource seals remain intact.
