# Normal-scenario applicability

The original caller reads this short contract before loading this qualifier's
`SKILL.md` or full contract. The caller judges whether dedicated admission is
needed; it does not give a qualification verdict here.

Invoke for a new or materially changed, real scenario admission candidate when
the caller would add a behavior to scope, acceptance, tests, findings,
implementation or blocking obligations, and its authority, supported honest
entry, reproduction or current-task necessity still needs dedicated admission.
This includes an observed responsibility contract defect or a real scope dispute.
Clear accepted ordinary work and routine verification do not create a candidate
merely because a stage boundary was reached. Existing explicit exclusions and
secret, permission and destructive-action obligations remain effective; a
candidate claiming one of them still follows the same applicability judgment.

For the same scenario, adopt a still-applicable conclusion available in the
conversation or an original owner gate that already needs it. A stage, caller,
HEAD or unrelated file change alone does not repeat admission. Material changes
to scope, authority, scenario, supported entry/consumer, conditions, reproduction or
task necessity refresh the affected judgment. Obtain a lost necessary conclusion
from its original owner or judge it again from live sources; never infer pass.

When invocation is needed, explicitly load the original Skill and complete
`contract.md`, submit the actual applicable nonempty candidate set, and consume
its original exit and unique consumer. Uncertain applicability with a real
candidate enters this owner; unavailable facts keep their original gap route.
When not triggered, do not load the full qualifier, assemble input, invoke an
empty check or create a classified/skipped result. The caller still performs
its own stage judgment. New invocations bind current facts; adoption never
replays an earlier invocation envelope. No applicability artifact is written.
