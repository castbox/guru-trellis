# Selected legacy Task maintenance

`judgment_mode=semantic`. This independent boundary is loaded from the complete
matching Guru source and its runtime. The target checkout is invocation context,
not dispatcher/runtime authority. Public API1.0 and the matching CLI/Core package
bytes are required before target writes. `local_candidate` is isolated development
proof only; a missing formal locked capability blocks real source-locked usage.

## Forward behavior

Read the explicit checkout, TaskKey and task_ref through public inspectTaskTarget.
Do not require current Identity, Continuation, ready, Closure or Reconcile first.
Read the preserved accepted scope, actual old Task and five planning artifacts,
historical source inventory, bindings and unresolved external responsibilities.
Classify the intended outcome: continued development, pending acceptance,
migration before closeout, or historical retention only. Status and merged PRs
never select an outcome. Retain completedAt/raw source rather than creating
current lifecycle timestamps or pass results.

For `convert`, AI authors a complete public Task2 projection and five-artifact
preserve/write map. Public Trellis owns validation and conversion; do not add a
Guru Task writer. Verify PR history through original Publish then Merge
`legacy_history_verification`; manually attributed commits remain with their
original fact owner and the public verifier. Unknown historical facts retain
source_snapshot dispositions and concrete missing evidence. Do not import a
historical gate as current authority. Existing IDs are fixed once, never recreated
on retries. Review any required target tools upgrade as a separate operation;
this Skill never silently installs tools or merges a baseline. Reconcile retains
business-diff judgment after parsing becomes possible.

For the public legacy-fact dispositions, inspect the original Task's `commit`,
`pr_url`, and `completedAt` values. A retained fact is a field that is present
and whose value is neither `null` nor the empty string. Supply exactly one
disposition for each such fact. Omit dispositions for missing, `null`, or empty
fields; when all three lack a fact, the disposition array is empty. Preserve
the original raw Task bytes. An actual nonempty historical value whose external
verification is unavailable remains a fact: retain it as `source_snapshot`
with the concrete evidence gap. Do not infer a current result or timestamp.
These are the matching public executor's existing attribution rules.

`legacy_fact_attribution_required` is an objective input error from that
executor, not a typed Skill exit. Compare the disposition fields with those
three actual source values, correct missing, duplicate, or extra dispositions,
review the corrected decisions, and repeat this owner's original prepare.
The failed prepare supplies no plan to apply. Do not alter the source snapshot
or bypass the original fact validator to make preparation succeed.

For `archive_resume`, select the exact monthly archive, its `original_task_ref`
and destination `active_ref`. Public inspection receives original_task_ref; the
old dispatcher, a current binding and manual relocation are not prerequisites.
AI reads the manual closeout note, source/accepted scope, historical Deliveries,
sessions, bindings and unfinished obligations. A manual historical archive has
no formal Completion/Closure/Finish and no pending closeout transaction. A
normally finished current archive enters `guru-reactivate-task`, including its
legal manual Cleanup. Pending Closure/Finish or an old Finalizer returns to its
original transaction or established manual disposition. Do not retire that
transaction as historical controls. Status or a merged PR cannot decide this.

Require the selected pair's additive `task_resume` capability and public
`prepareArchivedTaskResume`. Supply its complete projection, owner-authored
accepted_scope, exact artifact/session/binding dispositions and resume_intent
(reason/archive_review AuthorityRefs, next_owner_id and next_action). Public
Trellis owns format, provenance, generation and data writes. Preserve raw archive
and planning; do not create a substitute Task, empty Delivery, current pass or
completed timestamp. Verify historical PR/commit attribution with original
Publish/Merge before projection; retain unknown facts as explicit gaps.

For `history_closeout`, author a concrete public archive/note preserving original
history and external obligations. No tools upgrade is required. Do not call
normal Completion, Closure, Finish, cleanup, push or merge to fabricate a terminal
business result. Public owner persists/reads raw archive before retiring public
carriers/removing the active tree. Only then can original Guru owners retire
selected private controls.

## AI gate and exact execution

Review selection uniqueness, attribution, source compatibility, projection
sufficiency, preserved obligations, exact public/private write sets and intended
next actual owner. Inspect all actual Guru private carrier inventory using its
old source definition. Select only exact files attributed to this Task/generation;
unknown owner/path blocks before writes. Do not manufacture empty gate owners.
Review external PR/push/merge facts with the original owner and preserve unresolved
facts in history_note. Inspect original owner control files before public writes.
Keep terminal Finish results and sealed resources intact. For archive resume,
original private owners receive task_ref=original_task_ref for attribution and
source_task_ref=archive task_ref for physical Task bytes. Each owner validates
and freezes its own exact source/control preimages; the coordinator never
interprets its control state or deletes its namespace.

Only actual choices and concrete side effects need current-dialogue confirmation.
Never serialize authorization, its status or its process.

`scripts/preview.sh --root TARGET --input PUBLIC --action inspect` is read-only.
`--action prepare --plan DECISIONS` accepts owner-private `upstream_input`,
`control_refs` (owner id to exact file refs), and `history_note`; returns a
read-only prepared result. Review that exact prepared object and its write set.
`--action apply --plan PREPARED` freezes the same public operation/preimages in
ignored target runtime before writes. Do not reprepare to retry. Public and Guru
backups stay independent. Actual public conversion backup/archive must be readable,
then retire Publish → Merge → Finish → any explicitly supported other original
owner. Unsupported required owners block preparation. Private retirement inputs
contain exact selected Task, preserved_source_ref, control_refs and original

both the unchanged original archive and public active migration/source-task.json.
Persist only the public returned resumed_task key/ref for same-operation recovery;
finalization reads that active locator, never the archive or original path.

## Recovery and real target verification

`resume` and `rollback` have their own public input schemas with only original
recovery_ref. Resume preserves the fixed plan/Delivery/result/operation identity,
checks the same source and preimages, and never expands backups. Later owned edits
block overwrite; unrelated business work is untouched. Rollback validates all
private postimages before public restoration; public compatibility must pass
before Guru controls are restored. Incompatible tools/data rollback requires a
new reviewed combined scope, never automatic widening.

After mutation `resume_required` routes automatically to this owner; it is not
business completion. Before finalization, use `--action observe --plan REQUEST`
through scripts/preview.sh with actual target-native argv. Native must be the target checkout's own entry,
not the external maintenance runtime. For convert and archive_resume additionally run the next actual owner. Verify
target installed Identity, checkout, branch binding, Bind and native continuation
against the returned active TaskKey with a real session or lawful explicit-task
route. Initial prebinding Identity validates the active artifact through the
public schema parser and existing active occupancy before original C4 binding;
postbinding execution uses the official active resolver with selected checkout.
Scope changes enter original Clarify while preserving historical scope;
only a real new implementation slice enters Delivery/Planning. Delivered pending
acceptance enters actual Completion evidence_pending without an empty Delivery.
Read actual Task/planning/session/branch facts. AI judges native continuation and
owner output, not JSON syntax or process exit alone. History closeout runs old
normal context/current and proves the old Task is no longer selected while other
Task/session facts persist.

### Finalize review input

After reviewing the actual native and next-owner behavior, supply REVIEW as a
JSON file or `-` for stdin to `--action finalize --review-input REVIEW`. It has
these required fields:

| Field | Value and profile |
| --- | --- |
| `native_argv` | The actual target-native command's nonempty string array. |
| `next_owner_argv` | Required for `convert` and `archive_resume`: the actual next-owner command's nonempty string array. It is not required or executed for `history_closeout`. |
| `observations` | Copy the complete observation object from this owner's original `preview.sh --action observe` receipt at `result.result`. It contains `native`, plus `next_owner` for `convert` and `archive_resume`. |
| `output` | The minimal AI-selected `task_resumed` or `history_archived` output under the existing output schema. |

Each object inside `observations` contains the original `argv`, `returncode`,
`stdout` and `stderr`. Keep their complete values. The two existing intermediate
receipt envelopes are not observations. Do not flatten the object into top-level
`native_observation` or `next_owner_observation` fields, edit captured output, or
use private recovery state to infer this input.

See [the task-resumed example](../examples/finalize-review-task-resumed.json) for
`convert` and `archive_resume`, and
[the history-archived example](../examples/finalize-review-history-archived.json)
for `history_closeout`. These are illustrative shapes: replace their commands,
observations and output identity with this operation's actual reviewed values.
They are not current evidence or a passed gate.

Finalization checks the required input fields before executing either command.
Missing fields return their `review_input` location and this contract's repair
route. Extra caller fields keep their existing handling; this is not a new closed
input schema. Correct only the caller input and retain the same `recovery_ref`.
Then the original executor reruns the actual commands and compares their full
observations. It retains the existing output, route and identity checks before
recording the terminal result. The validator never decides a semantic route from
status. Native success alone is insufficient: AI must assess the actual output
and next owner behavior.

## Typed exits and consumers

- task_resumed: minimum current Task identity to original normal continuation;
  data conversion, native session and next owner have actually been verified.
- history_archived: selected key/archive_ref to historical-retention stop; no
  Completion/Closure/Finish success is implied.
- resume_required: original recovery_ref to this owner's resume input.
- rolled_back: selected key to result stop after both halves restore compatibly.
- blocked: concrete reason/remediation to stop; never a reinstall loop.

Report tool usability, data conversion, native session restoration, historical
Delivery restoration and business completion separately. Public API, original
owner and native observations establish only their actual layers. Whole-task
business acceptance remains with its current owner.
